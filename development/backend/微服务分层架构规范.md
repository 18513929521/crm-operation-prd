# 微服务分层架构规范

## 1. 概述

本文档定义了CRM运营平台中各个微服务的内部分层架构标准和开发规范，确保所有微服务遵循统一的代码结构和设计模式。

## 2. 分层架构概述

每个微服务采用DDD领域驱动设计思想，采用标准的分层架构模式，确保代码结构清晰、职责分明、易于维护。

```
┌─────────────────────────────────────────────────────────────┐
│                     Presentation Layer                      │
│                    (Controller / API)                       │
│                  接收请求、参数验证、返回响应                  │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                      Service Layer                          │
│                    (Business Logic)                         │
│               业务逻辑处理、事务控制、服务编排                 │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                    Repository Layer                         │
│                   (Data Access Object)                      │
│                  数据访问、持久化操作                         │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                      Domain Layer                           │
│                   (Entity / Model)                          │
│                  领域模型、业务实体                           │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 分层依赖关系

```
Controller  →  Service  →  Repository(接口)  ←  RepositoryImpl  →  Mapper + Converter
                                                                          ↓
                                                                         PO
```

**关键设计原则：**
1. Service层只依赖Repository接口，不依赖具体实现
2. Repository接口使用Entity（领域实体）作为参数和返回值
3. RepositoryImpl负责调用Mapper并进行PO与Entity的转换
4. Mapper只操作PO（持久化对象），与数据库表一对一映射
5. 未来更换存储引擎时，只需替换RepositoryImpl，不影响业务层

## 4. 各层职责说明

### 4.1 Controller层（控制层）

#### 职责
- 接收HTTP请求，进行参数校验
- 调用Service层处理业务逻辑
- 封装统一的响应格式返回给客户端
- 不包含业务逻辑处理

#### 开发规范
- 使用`@RestController`注解
- 使用`@RequestMapping`定义路由
- 使用`@Validated`进行参数校验
- 统一使用`Result<T>`封装返回结果
- 避免在Controller层写业务逻辑

#### 代码示例
```java
@RestController
@RequestMapping("/v1/tenant")
@Slf4j
public class TenantController {
    
    @Autowired
    private TenantService tenantService;
    
    @PostMapping("/create")
    public Result<TenantVO> createTenant(@Validated @RequestBody TenantDTO tenantDTO) {
        TenantVO tenant = tenantService.createTenant(tenantDTO);
        return Result.success(tenant);
    }
    
    @GetMapping("/{id}")
    public Result<TenantVO> getTenant(@PathVariable Long id) {
        TenantVO tenant = tenantService.getTenantById(id);
        return Result.success(tenant);
    }
    
    @PutMapping("/{id}")
    public Result<Void> updateTenant(@PathVariable Long id, 
                                     @Validated @RequestBody TenantDTO tenantDTO) {
        tenantService.updateTenant(id, tenantDTO);
        return Result.success();
    }
    
    @DeleteMapping("/{id}")
    public Result<Void> deleteTenant(@PathVariable Long id) {
        tenantService.deleteTenant(id);
        return Result.success();
    }
    
    @GetMapping("/page")
    public Result<Page<TenantVO>> getTenantPage(@Validated TenantQuery query) {
        Page<TenantVO> page = tenantService.getTenantPage(query);
        return Result.success(page);
    }
}
```

### 4.2 Service层（业务逻辑层）

#### 职责
- 实现核心业务逻辑
- 事务管理和控制
- 调用Repository层进行数据操作
- 服务编排和组合
- 调用其他微服务接口

#### 开发规范
- 接口定义在`service`包，实现类在`service.impl`包
- 使用`@Service`注解
- 使用`@Transactional`进行事务管理
- 复杂业务逻辑需要添加详细注释
- 避免在Service层直接操作数据库

#### 代码示例
```java
public interface TenantService {
    TenantVO createTenant(TenantDTO tenantDTO);
    TenantVO getTenantById(Long id);
    void updateTenant(Long id, TenantDTO tenantDTO);
    void deleteTenant(Long id);
    Page<TenantVO> getTenantPage(TenantQuery query);
}

@Service
@Slf4j
public class TenantServiceImpl implements TenantService {
    
    @Autowired
    private TenantRepository tenantRepository;
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    @Override
    @Transactional(rollbackFor = Exception.class)
    public TenantVO createTenant(TenantDTO tenantDTO) {
        log.info("开始创建租户，参数：{}", JSON.toJSONString(tenantDTO));
        
        // 1. DTO转Entity
        Tenant tenant = new Tenant();
        tenant.setTenantName(tenantDTO.getTenantName());
        tenant.setTenantCode(tenantDTO.getTenantCode());
        tenant.setDescription(tenantDTO.getDescription());
        tenant.setStatus(TenantStatus.ACTIVE);
        tenant.setCreateTime(LocalDateTime.now());
        
        // 2. 业务规则校验
        tenantRepository.findByTenantCode(tenant.getTenantCode())
                .ifPresent(t -> {
                    throw new BusinessException("租户编码已存在");
                });
        
        // 3. 保存到数据库（通过Repository接口）
        Tenant saved = tenantRepository.save(tenant);
        
        // 4. 缓存处理
        String cacheKey = "tenant:" + saved.getId();
        redisTemplate.opsForValue().set(cacheKey, saved, 1, TimeUnit.HOURS);
        
        log.info("租户创建成功，租户ID：{}", saved.getId());
        
        // 5. Entity转VO返回
        return convertToVO(saved);
    }
    
    @Override
    public TenantVO getTenantById(Long id) {
        // 1. 先查缓存
        String cacheKey = "tenant:" + id;
        Tenant cached = (Tenant) redisTemplate.opsForValue().get(cacheKey);
        if (cached != null) {
            return convertToVO(cached);
        }
        
        // 2. 缓存未命中，从Repository查询
        Tenant tenant = tenantRepository.findById(id)
                .orElseThrow(() -> new BusinessException("租户不存在"));
        
        // 3. 更新缓存
        redisTemplate.opsForValue().set(cacheKey, tenant, 1, TimeUnit.HOURS);
        
        return convertToVO(tenant);
    }
    
    @Override
    @Transactional(rollbackFor = Exception.class)
    public void updateTenant(Long id, TenantDTO tenantDTO) {
        // 1. 查询租户
        Tenant tenant = tenantRepository.findById(id)
                .orElseThrow(() -> new BusinessException("租户不存在"));
        
        // 2. 业务规则校验
        if (!tenant.canModify()) {
            throw new BusinessException("租户状态不允许修改");
        }
        
        // 3. 更新数据
        tenant.setTenantName(tenantDTO.getTenantName());
        tenant.setDescription(tenantDTO.getDescription());
        tenant.setUpdateTime(LocalDateTime.now());
        
        // 4. 保存更新
        tenantRepository.update(tenant);
        
        // 5. 删除缓存
        String cacheKey = "tenant:" + id;
        redisTemplate.delete(cacheKey);
    }
    
    @Override
    @Transactional(rollbackFor = Exception.class)
    public void deleteTenant(Long id) {
        tenantRepository.deleteById(id);
        
        // 删除缓存
        String cacheKey = "tenant:" + id;
        redisTemplate.delete(cacheKey);
    }
    
    @Override
    public Page<TenantVO> getTenantPage(TenantQuery query) {
        // 通过Repository分页查询
        Page<Tenant> page = tenantRepository.findPage(query);
        
        // Entity转VO
        List<TenantVO> voList = page.getRecords().stream()
                .map(this::convertToVO)
                .collect(Collectors.toList());
        
        return new Page<>(voList, page.getTotal(), page.getCurrent(), page.getSize());
    }
    
    /**
     * Entity转VO
     */
    private TenantVO convertToVO(Tenant tenant) {
        TenantVO vo = new TenantVO();
        vo.setId(tenant.getId());
        vo.setTenantName(tenant.getTenantName());
        vo.setTenantCode(tenant.getTenantCode());
        vo.setDescription(tenant.getDescription());
        vo.setStatus(tenant.getStatus().getCode());
        vo.setStatusName(tenant.getStatus().getDesc());
        vo.setCreateTime(tenant.getCreateTime());
        vo.setUpdateTime(tenant.getUpdateTime());
        return vo;
    }
}
```

### 4.3 Repository层（仓储层）

#### 职责
- 定义数据访问接口，使用领域实体（Entity）
- 封装数据访问逻辑，对业务层隐藏存储细节
- 不依赖具体的存储实现

#### 开发规范
- Repository是接口，定义在`repository`包
- Repository实现类放在`repository.impl`包
- Repository接口使用Entity作为参数和返回值
- RepositoryImpl负责调用Mapper和进行对象转换

#### 代码示例

**1. Repository接口：**
```java
public interface TenantRepository {
    
    /**
     * 保存租户
     */
    Tenant save(Tenant tenant);
    
    /**
     * 根据ID查询租户
     */
    Optional<Tenant> findById(Long id);
    
    /**
     * 根据租户编码查询
     */
    Optional<Tenant> findByTenantCode(String tenantCode);
    
    /**
     * 更新租户
     */
    void update(Tenant tenant);
    
    /**
     * 删除租户
     */
    void deleteById(Long id);
    
    /**
     * 分页查询租户列表
     */
    Page<Tenant> findPage(TenantQuery query);
    
    /**
     * 批量更新状态
     */
    int updateStatusBatch(List<Long> ids, Integer status);
}
```

**2. Repository实现类：**
```java
@Repository
public class TenantRepositoryImpl implements TenantRepository {
    
    @Autowired
    private TenantMapper tenantMapper;
    
    @Autowired
    private TenantConverter tenantConverter;
    
    @Override
    public Tenant save(Tenant tenant) {
        TenantPO po = tenantConverter.toPO(tenant);
        tenantMapper.insert(po);
        return tenantConverter.toEntity(po);
    }
    
    @Override
    public Optional<Tenant> findById(Long id) {
        TenantPO po = tenantMapper.selectById(id);
        return Optional.ofNullable(po)
                .map(tenantConverter::toEntity);
    }
    
    @Override
    public Optional<Tenant> findByTenantCode(String tenantCode) {
        TenantPO po = tenantMapper.selectByTenantCode(tenantCode);
        return Optional.ofNullable(po)
                .map(tenantConverter::toEntity);
    }
    
    @Override
    public void update(Tenant tenant) {
        TenantPO po = tenantConverter.toPO(tenant);
        tenantMapper.updateById(po);
    }
    
    @Override
    public void deleteById(Long id) {
        tenantMapper.deleteById(id);
    }
    
    @Override
    public Page<Tenant> findPage(TenantQuery query) {
        com.baomidou.mybatisplus.extension.plugins.pagination.Page<TenantPO> page = 
            new com.baomidou.mybatisplus.extension.plugins.pagination.Page<>(
                query.getPageNum(), query.getPageSize());
        
        IPage<TenantPO> result = tenantMapper.selectTenantPage(page, query);
        
        List<Tenant> entities = result.getRecords().stream()
                .map(tenantConverter::toEntity)
                .collect(Collectors.toList());
        
        return new Page<>(entities, result.getTotal(), result.getCurrent(), result.getSize());
    }
    
    @Override
    public int updateStatusBatch(List<Long> ids, Integer status) {
        return tenantMapper.updateStatusBatch(ids, status);
    }
}
```

### 4.4 Infrastructure层（基础设施层）

#### 4.4.1 Mapper接口（数据访问实现）

**职责：**
- MyBatis Mapper接口，操作PO对象
- 只关注数据库操作，不包含业务逻辑

**代码示例：**
```java
@Mapper
```

```java
@Component
public class TenantConverter {
    
    public Tenant toEntity(TenantPO po) {
        if (po == null) {
            return null;
        }
        
        Tenant entity = new Tenant();
        entity.setId(po.getId());
        entity.setTenantName(po.getTenantName());
        entity.setTenantCode(po.getTenantCode());
        entity.setDescription(po.getDescription());
        entity.setStatus(TenantStatus.fromCode(po.getStatus()));
        entity.setCreateTime(po.getCreateTime());
        entity.setUpdateTime(po.getUpdateTime());
        
        return entity;
    }
    
    public TenantPO toPO(Tenant entity) {
        if (entity == null) {
            return null;
        }
        
        TenantPO po = new TenantPO();
        po.setId(entity.getId());
        po.setTenantName(entity.getTenantName());
        po.setTenantCode(entity.getTenantCode());
        po.setDescription(entity.getDescription());
        po.setStatus(entity.getStatus() != null ? entity.getStatus().getCode() : null);
        po.setCreateTime(entity.getCreateTime());
        po.setUpdateTime(entity.getUpdateTime());
        
        return po;
    }
    
    public List<Tenant> toEntityList(List<TenantPO> poList) {
        if (poList == null || poList.isEmpty()) {
            return Collections.emptyList();
        }
        return poList.stream()
                .map(this::toEntity)
                .collect(Collectors.toList());
    }
```

## 10. Repository-Mapper分离架构优势

### 10.1 架构设计理念

本架构采用Repository模式结合DDD（领域驱动设计）思想，将业务逻辑与存储实现完全解耦。

**分层依赖图：**
```
┌─────────────┐
│   Service   │ ← 业务层，只依赖Repository接口，使用Entity
└─────────────┘
       ↓ 依赖
┌─────────────┐
│ Repository  │ ← 接口层，定义数据访问契约
│ (Interface) │
└─────────────┘
       ↑ 实现
┌─────────────┐
│ Repository  │ ← 实现层，负责Entity↔PO转换
│   Impl      │
└─────────────┘
       ↓ 调用
┌─────────────┐     ┌─────────────┐
│   Mapper    │ ←→  │  Converter  │
│(MyBatis)    │     │(PO↔Entity)  │
└─────────────┘     └─────────────┘
       ↓
┌─────────────┐
│     PO      │ ← 持久化对象，与数据库表映射
└─────────────┘
```

### 10.2 核心优势

#### 1. 存储引擎可替换

**场景示例：从MySQL切换到MongoDB**

**传统方式（直接使用Mapper）：**
```java
// Service层直接依赖MyBatis Mapper，业务逻辑与存储耦合
@Service
public class TenantServiceImpl {
    @Autowired
    private TenantMapper tenantMapper;  // 依赖具体实现
    
    public Tenant findById(Long id) {
        TenantPO po = tenantMapper.selectById(id);  // MyBatis API
        return convertToEntity(po);
    }
}
// 切换存储引擎需要修改所有Service代码！
```

**Repository模式：**
```java
// Service层只依赖Repository接口，不知道具体存储
@Service
public class TenantServiceImpl {
    @Autowired
    private TenantRepository tenantRepository;  // 依赖抽象接口
    
    public Tenant findById(Long id) {
        return tenantRepository.findById(id).orElse(null);  // 统一API
    }
}

// 方式1：MyBatis实现
@Repository
public class TenantRepositoryMybatisImpl implements TenantRepository {
    @Autowired
    private TenantMapper tenantMapper;
    // ...
}

// 方式2：MongoDB实现（切换时Service层不需要改动）
@Repository
public class TenantRepositoryMongoImpl implements TenantRepository {
    @Autowired
    private MongoTemplate mongoTemplate;
    // ...
}
```

**结论：** Service层代码无需修改，只需更换Repository实现！

#### 2. 业务模型与数据库表解耦

**Entity vs PO 对比：**

| 维度 | Entity（领域实体） | PO（持久化对象） |
|------|-------------------|------------------|
| 职责 | 业务领域模型 | 数据库表映射 |
| 位置 | domain/entity | infrastructure/po |
| 类型 | 业务类型（枚举、值对象） | 数据库类型（Integer、String） |
| 方法 | 包含业务规则和验证 | 纯数据载体，无业务逻辑 |
| 依赖 | 不依赖框架 | 依赖MyBatis-Plus注解 |
| 变化 | 随业务需求变化 | 随数据库表结构变化 |

**实际示例：**

**Entity（面向业务）：**
```java
@Data
public class Tenant {
    private Long id;
    private String tenantName;
    private TenantStatus status;  // 业务枚举
    
    // 业务方法
    public void activate() {
        this.status = TenantStatus.ACTIVE;
    }
    
    public boolean isActive() {
        return this.status == TenantStatus.ACTIVE;
    }
}

public enum TenantStatus {
    ACTIVE, DISABLED, DELETED
}
```

**PO（面向数据库）：**
```java

    @TableId
    private Long id;
    
    @TableField("tenant_name")
    private String tenantName;
    
    @TableField("status")

```

**好处：**
- 数据库表结构变化不影响业务代码
- 业务模型可以自由设计，不受数据库约束
- 可以轻松实现一个Entity对应多个表（聚合根）

#### 3. 支持多数据源和混合存储

**场景：租户基本信息存MySQL，租户统计数据存Redis**

```java
@Repository
public class TenantRepositoryImpl implements TenantRepository {
    
    @Autowired
    private TenantMapper mysqlMapper;  // MySQL
    
    @Autowired
    private RedisTemplate redisTemplate;  // Redis
    
    @Override
    public Tenant findById(Long id) {
        // 1. 从MySQL读取基本信息
        TenantPO po = mysqlMapper.selectById(id);
        Tenant tenant = converter.toEntity(po);
        
        // 2. 从Redis读取统计数据
        TenantStatistics stats = (TenantStatistics) redisTemplate
                .opsForValue().get("tenant:stats:" + id);
        tenant.setStatistics(stats);
        
        return tenant;
    }
    
    @Override
    public void save(Tenant tenant) {
        // 1. 基本信息存MySQL
        TenantPO po = converter.toPO(tenant);
        mysqlMapper.insert(po);
        
        // 2. 统计数据存Redis
        redisTemplate.opsForValue().set(
            "tenant:stats:" + tenant.getId(), 
            tenant.getStatistics()
        );
    }
}
```

**Service层完全不知道数据来自哪里！**

#### 5. 符合SOLID原则

- **S（单一职责）**：Repository负责数据访问，Mapper负责SQL映射，各司其职
- **O（开闭原则）**：扩展新的存储实现，无需修改现有代码
- **L（里氏替换）**：任何Repository实现都可以替换，不影响业务
- **I（接口隔离）**：Repository接口只定义业务需要的方法
- **D（依赖倒置）**：Service依赖Repository抽象，不依赖具体实现

### 10.3 实施建议

#### 1. 命名规范

```
domain/entity/Tenant.java           ← 领域实体（不带后缀）
infrastructure/po/TenantPO.java     ← 持久化对象（PO后缀）
repository/TenantRepository.java    ← 仓储接口（Repository后缀）
repository/impl/TenantRepositoryImpl.java  ← 实现类（Impl后缀）
```

#### 2. 转换器推荐

- **简单场景**：手动转换（性能最好）
- **复杂场景**：MapStruct（编译期生成，类型安全）
- **不推荐**：BeanUtils.copyProperties（运行时反射，性能差）

#### 3. 渐进式迁移

如果是旧项目改造，可以渐进式迁移：

1. **第一步**：新功能使用Repository模式
2. **第二步**：核心模块改造为Repository模式
3. **第三步**：逐步重构所有模块

### 10.4 常见问题

**Q1: 是否所有查询都要通过Repository？**  
A: 是的。Service层不应直接调用Mapper，所有数据访问都通过Repository。

**Q2: 简单CRUD也要加Converter吗？**  
A: 是的。即使Entity和PO结构相同，也应该通过Converter转换。这是为了保持架构一致性，便于未来扩展。

**Q3: Repository方法命名规范？**  
A: 建议使用：
- `save` / `update` / `delete`
- `findById` / `findByXxx`
- `existsByXxx`
- `countByXxx`

**Q4: 是否需要增加DAO层？**  
A: 不需要。Repository就是DAO层的抽象，Mapper是Repository的实现细节。
