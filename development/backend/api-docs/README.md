## 文档规范

### 命名规范

1. **目录命名**: 使用应用的服务名称（如 `crm-operation-system`）
2. **文件命名**: 
   - `system-api.md` - 对外提供的业务API
   - `internal-api.md` - 服务间调用的内部API
   - `admin-api.md` - 管理后台专用API（如需要）

### 文档内容

每个API文档应包含：

1. **概述** - 应用简介、基础路径、认证方式
2. **接口列表** - 按功能模块分组的接口清单
3. **请求示例** - 包含请求参数、请求头
4. **响应示例** - 包含成功和失败响应
5. **错误码说明** - 统一的错误码对照表
6. **使用场景** - 典型使用场景和代码示例
7. **注意事项** - 重要提示和最佳实践

### 统一响应格式

所有应用统一使用以下响应格式：

**成功响应**:
```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... },
  "timestamp": 1728893400000
}
```

**错误响应**:
```json
{
  "code": 404,
  "message": "请求的资源不存在",
  "data": null,
  "timestamp": 1728893400000
}
```

### 统一错误码

| 错误码 | HTTP状态码 | 说明 |
|--------|-----------|------|
| 200 | 200 | 操作成功 |
| 400 | 200 | 参数校验失败 |
| 401 | 200 | 未授权（未登录或Token无效） |
| 403 | 200 | 禁止访问（账号已禁用） |
| 404 | 404 | 资源不存在（接口不存在或数据不存在） |
| 500 | 500 | 系统异常 |
