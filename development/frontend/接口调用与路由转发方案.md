# CRM运营平台 - 前端接口调用与路由转发方案

## 1. 概述

本文档定义了CRM运营平台前端如何调用后端API，以及Nginx和Gateway如何进行请求路由和转发。

### 1.1 架构流程

```
前端应用 → Nginx → Gateway → 微服务
```

**各层职责：**
- **前端**：发起HTTP请求，调用统一的API路径
- **Nginx**：反向代理，将API请求转发到Gateway
- **Gateway**：路由分发，根据路径将请求转发到对应的微服务
- **微服务**：处理业务逻辑，返回响应

## 2. 接口路径规范

### 2.1 URL格式设计

**统一格式：** `/api/{service}/v1/{resource}`

**说明：**
- `api`：API标识前缀
- `{service}`：服务标识（如 system、tenant、application）
- `v1`：API版本号
- `{resource}`：资源路径（如 users、tenants）

### 2.2 服务路径对照表

| 微服务 | 服务标识 | 前端调用路径 | Gateway转发路径 | 微服务实际接口 |
|-------|---------|------------|----------------|---------------|
| 系统管理 | system | `/api/system/v1/users` | `/v1/users` | `@RequestMapping("/v1/users")` |
| 租户管理 | tenant | `/api/tenant/v1/tenants` | `/v1/tenants` | `@RequestMapping("/v1/tenants")` |
| 应用管理 | application | `/api/application/v1/applications` | `/v1/applications` | `@RequestMapping("/v1/applications")` |
| 角色权限模板 | role-template | `/api/role-template/v1/roles` | `/v1/roles` | `@RequestMapping("/v1/roles")` |
| 基础设施 | infrastructure | `/api/infrastructure/v1/configs` | `/v1/configs` | `@RequestMapping("/v1/configs")` |
| 工作流引擎 | workflow | `/api/workflow/v1/processes` | `/v1/processes` | `@RequestMapping("/v1/processes")` |

**路径转换规则：**
```
前端：/api/{service}/v1/{resource}
       ↓ Gateway使用StripPrefix=2去掉/api/{service}
微服务：/v1/{resource}
```

### 3.2 Axios实例配置

**shared/utils/request.js**

```javascript
import axios from 'axios';
import { ElMessage } from 'element-plus';
import router from '@/router';

// 创建axios实例
const request = axios.create({
  baseURL: import.meta.env.VITE_API_GATEWAY || '/api',
  timeout: 10000,
  headers: {
    'Content-Type': 'application/json'
  }
});

// 请求拦截器
request.interceptors.request.use(
  config => {
    // 添加Token
    const token = localStorage.getItem('token');
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    
    // 添加租户ID（如果需要）
    const tenantId = localStorage.getItem('tenantId');
    if (tenantId) {
      config.headers['X-Tenant-Id'] = tenantId;
    }
    
    return config;
  },
  error => {
    return Promise.reject(error);
  }
);

// 响应拦截器
request.interceptors.response.use(
  response => {
    const { code, message, data } = response.data;
    
    if (code === 200) {
      return data;
    } else {
      ElMessage.error(message || '请求失败');
      return Promise.reject(new Error(message));
    }
  },
  error => {
    const { response } = error;
    
    if (response?.status === 401) {
      // 未授权，跳转登录
      ElMessage.error('登录已过期，请重新登录');
      localStorage.removeItem('token');
      router.push('/login');
    } else if (response?.status === 403) {
      // 无权限
      ElMessage.error('您没有权限访问该资源');
    } else if (response?.status === 404) {
      // 资源不存在
      ElMessage.error('请求的资源不存在');
    } else if (response?.status === 500) {
      // 服务器错误
      ElMessage.error('服务器错误，请稍后重试');
    } else {
      ElMessage.error(error.message || '网络错误');
    }
    
    return Promise.reject(error);
  }
);

export default request;
```

### 3.5 使用示例

```vue
<script setup>
import { ref, onMounted } from 'vue';
import { userApi } from '@/api';
import { ElMessage } from 'element-plus';

const userList = ref([]);
const loading = ref(false);

// 获取用户列表
const fetchUsers = async () => {
  loading.value = true;
  try {
    // 前端调用: /api/system/v1/users
    const data = await userApi.getList({
      page: 1,
      size: 10
    });
    userList.value = data.list;
  } catch (error) {
    console.error('获取用户列表失败', error);
  } finally {
    loading.value = false;
  }
};

onMounted(() => {
  fetchUsers();
});
</script>
```

## 4. Nginx配置

### 4.1 开发环境配置

**开发环境使用Vite代理：**

**主应用 vite.config.js**

```javascript
export default defineConfig({
  server: {
    port: 8080,
    proxy: {
      // 所有/api请求代理到Gateway
      '/api': {
        target: 'http://localhost:18100',  // Gateway地址
        changeOrigin: true
        // 不做路径改写，直接转发到Gateway
        // Gateway会根据路径路由到对应微服务
      }
    }
  }
});
```

**微应用独立开发时代理配置（统一通过Gateway）：**

所有微应用开发时统一通过Gateway调用后端接口，与主应用保持一致：

**说明：**

- 前端调用路径保持不变：`/api/{service}/v1/{resource}`
- Gateway负责路由分发和路径转换
- 确保开发环境与生产环境保持一致的调用方式

### 4.2 生产环境Nginx配置

**nginx.conf**

```nginx
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log warn;
pid /var/run/nginx.pid;

events {
    worker_connections 1024;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    
    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';
    
    access_log /var/log/nginx/access.log main;
    
    sendfile on;
    tcp_nopush on;
    tcp_nodelay on;
    keepalive_timeout 65;
    
    # Gzip压缩
    gzip on;
    gzip_vary on;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_types text/plain text/css text/xml text/javascript 
               application/json application/javascript application/xml+rss;
    
    # 上游服务器 - Gateway
    upstream gateway {
        server gateway:18100;
        # 如果Gateway有多个实例，可以配置负载均衡
        # server gateway-1:18100;
        # server gateway-2:18100;
    }
    
    server {
        listen 80;
        server_name operation.example.com;
        
        # ====================================
        # 前端静态资源
        # ====================================
        
        # 主应用
        location / {
            root /usr/share/nginx/html;
            try_files $uri $uri/ /index.html;
            add_header Cache-Control "no-cache, no-store, must-revalidate";
        }
        
        # 系统管理微应用
        location /system {
            alias /usr/share/nginx/html/system;
            try_files $uri $uri/ /system/index.html;
            add_header Cache-Control "no-cache, no-store, must-revalidate";
        }
        
        # 租户管理微应用
        location /tenant {
            alias /usr/share/nginx/html/tenant;
            try_files $uri $uri/ /tenant/index.html;
            add_header Cache-Control "no-cache, no-store, must-revalidate";
        }
        
        # 应用管理微应用
        location /application {
            alias /usr/share/nginx/html/application;
            try_files $uri $uri/ /application/index.html;
            add_header Cache-Control "no-cache, no-store, must-revalidate";
        }
        
        # 角色权限模板微应用
        location /role-template {
            alias /usr/share/nginx/html/role-template;
            try_files $uri $uri/ /role-template/index.html;
            add_header Cache-Control "no-cache, no-store, must-revalidate";
        }
        
        # 静态资源缓存（JS、CSS、图片等）
        location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
            root /usr/share/nginx/html;
            expires 30d;
            add_header Cache-Control "public, immutable";
            access_log off;
        }
        
        # ====================================
        # API反向代理 - 转发到Gateway
        # ====================================
        
        # 所有API请求转发到Gateway
        location /api/ {
            proxy_pass http://gateway/api/;
            
            # 请求头设置
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            
            # WebSocket支持
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection "upgrade";
            
            # 超时配置
            proxy_connect_timeout 60s;
            proxy_send_timeout 60s;
            proxy_read_timeout 60s;
            
            # 缓冲区配置
            proxy_buffering on;
            proxy_buffer_size 4k;
            proxy_buffers 8 4k;
            proxy_busy_buffers_size 8k;
        }
    }
}
```

**配置说明：**
1. **前端静态资源**：直接由Nginx提供服务
2. **API请求**：所有 `/api/*` 请求转发到Gateway（18100端口）
3. **保持路径不变**：`proxy_pass http://gateway/api/` 保持完整路径转发

## 5. Gateway路由配置

### 5.1 Spring Cloud Gateway配置

**application.yml**

```yaml
spring:
  cloud:
    gateway:
      routes:
        # ====================================
        # 系统管理服务路由
        # ====================================
        - id: system-users
          uri: lb://crm-operation-system
          predicates:
            - Path=/api/system/v1/users/**
          filters:
            - StripPrefix=2  # 去掉 /api/system，保留 /v1/users/**
        
        - id: system-auth
          uri: lb://crm-operation-system
          predicates:

            - StripPrefix=2

        # 租户管理服务路由

          uri: lb://crm-operation-tenant
          predicates:

        # 应用管理服务路由
        # ====================================
        - id: application-management
          uri: lb://crm-operation-application

        - id: role-template-management
          uri: lb://crm-operation-role-template
          predicates:
            - Path=/api/role-template/v1/**

            - StripPrefix=2  # 去掉 /api/role-template，保留 /v1/**
        
        # ====================================
        # 基础设施服务路由
        # ====================================
        - id: infrastructure
          uri: lb://crm-operation-infrastructure
          predicates:
            - Path=/api/infrastructure/v1/**

          predicates:
            - Path=/api/workflow/v1/**

      # 全局配置
      globalcors:
        cors-configurations:
          '[/**]':
            allowedOrigins: "*"
            allowedMethods:
              - GET
              - POST
              - PUT

            allowedHeaders: "*"
```

**StripPrefix说明：**
- `StripPrefix=2`：去掉路径的前2段
- 例如：`/api/system/v1/users` → 去掉 `/api/system` → `/v1/users`
- 适用于后端Controller使用 `@RequestMapping("/v1/{resource}")` 的场景

### 5.2 Gateway配置方案

**后端Controller使用 `@RequestMapping("/v1/users")`，Gateway使用StripPrefix：**

**优势：**
- 配置更简洁，使用`StripPrefix`而不是复杂的`RewritePath`
- 后端不需要`/api`前缀，路径更清晰
- 符合RESTful最佳实践

**crm-operation-gateway/src/main/resources/application.yml**

```yaml
spring:
  application:
    name: crm-operation-gateway
  cloud:
    nacos:
      discovery:
        server-addr: ${NACOS_ADDR:localhost:8848}
        namespace: ${NACOS_NAMESPACE:operation-dev}
        group: GATEWAY_GROUP
    gateway:
      discovery:
        locator:
          enabled: false  # 禁用自动路由，使用手动配置
      routes:
        # ====================================
        # 系统管理服务（crm-operation-system）
        # ====================================
        - id: system-service
          uri: lb://crm-operation-system
          predicates:
            - Path=/api/system/**
          filters:
            - StripPrefix=2  # 去掉 /api/system
          # 转换: /api/system/v1/users → /v1/users
        
        # ====================================
        # 租户管理服务（crm-operation-tenant）
        # ====================================
        - id: tenant-service
          uri: lb://crm-operation-tenant
          predicates:
            - Path=/api/tenant/**
          filters:
            - StripPrefix=2  # 去掉 /api/tenant
          # 转换: /api/tenant/v1/tenants → /v1/tenants
        
        # ====================================
        # 应用管理服务（crm-operation-application）
        # ====================================
        - id: application-service
          uri: lb://crm-operation-application
          predicates:
            - Path=/api/application/**
          filters:
            - StripPrefix=2  # 去掉 /api/application
          # 转换: /api/application/v1/applications → /v1/applications
        
        # ====================================
        # 角色权限模板服务（crm-operation-role-template）
        # ====================================
        - id: role-template-service
          uri: lb://crm-operation-role-template
          predicates:
            - Path=/api/role-template/**
```

### 6.1 用户列表查询流程

```
1. 前端发起请求
   ↓
   userApi.getList() 
   → GET http://operation.example.com/api/system/v1/users?page=1&size=10
   
2. Nginx接收请求
   ↓
   location /api/ { proxy_pass http://gateway/api/; }

5. 微服务处理请求

   @RequestMapping("/api/v1/users")

   → 处理业务逻辑
```

```java
@Component
public class GlobalHeaderFilter implements GlobalFilter, Ordered {
    
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        ServerHttpRequest request = exchange.getRequest();
        
        // 添加请求ID（用于日志追踪）
        String requestId = UUID.randomUUID().toString();
        ServerHttpRequest modifiedRequest = request.mutate()
            .header("X-Request-Id", requestId)

        ServerWebExchange modifiedExchange = exchange.mutate()
            .request(modifiedRequest)
            .build();
        
        return chain.filter(modifiedExchange);
    }
    
    @Override
    public int getOrder() {
        return -100;  // 优先级高，先执行
    }
}
```

### 9.2 前端重试机制

```javascript
// utils/request.js
import axios from 'axios';

const request = axios.create({
  baseURL: import.meta.env.VITE_API_GATEWAY,
  timeout: 10000
});

// 添加重试拦截器
request.interceptors.response.use(
  response => response,
  async error => {
    const config = error.config;
    
    // 如果没有配置重试，或已经重试过，直接拒绝
    if (!config || !config.retry) {
      return Promise.reject(error);
    }
    
    // 设置重试计数
    config.__retryCount = config.__retryCount || 0;
    
    // 检查是否超过最大重试次数
    if (config.__retryCount >= config.retry) {
      return Promise.reject(error);
    }
    
    // 增加重试计数
    config.__retryCount += 1;
    
    // 只对网络错误或5xx错误重试
    if (!error.response || error.response.status >= 500) {
      console.log(`重试请求 ${config.url}，第 ${config.__retryCount} 次`);
      
      // 延迟后重试
      await new Promise(resolve => setTimeout(resolve, config.retryDelay || 1000));
      
      return request(config);
    }
    
    return Promise.reject(error);
  }
);

export default request;

// 使用示例
userApi.getList({}, {
  retry: 3,        // 最多重试3次
  retryDelay: 1000 // 重试延迟1秒
});
```

### 14.3 Token失效处理

**问题：** Token过期后如何处理

**解决方案：**

```javascript
// utils/request.js
let isRefreshing = false;
let failedQueue = [];

const processQueue = (error, token = null) => {
  failedQueue.forEach(prom => {
    if (error) {
      prom.reject(error);
    } else {
      prom.resolve(token);
    }
  });
  failedQueue = [];
};

request.interceptors.response.use(
  response => response,
  async error => {
    const originalRequest = error.config;
    
    if (error.response?.status === 401 && !originalRequest._retry) {
      if (isRefreshing) {
        // 正在刷新token，将请求加入队列
        return new Promise((resolve, reject) => {
          failedQueue.push({ resolve, reject });
        }).then(token => {
          originalRequest.headers.Authorization = `Bearer ${token}`;
          return request(originalRequest);
        });
      }
      
      originalRequest._retry = true;
      isRefreshing = true;
      
      try {
        // 刷新token
        const refreshToken = localStorage.getItem('refreshToken');
        const { token } = await authApi.refreshToken(refreshToken);
        
        // 更新token
        localStorage.setItem('token', token);
        originalRequest.headers.Authorization = `Bearer ${token}`;
        
        // 处理队列中的请求
        processQueue(null, token);
        
        return request(originalRequest);
      } catch (err) {
        // 刷新失败，跳转登录
        processQueue(err, null);
        localStorage.removeItem('token');
        localStorage.removeItem('refreshToken');
        router.push('/login');
        return Promise.reject(err);
      } finally {
        isRefreshing = false;
      }
    }
    
    return Promise.reject(error);
  }
);
```
