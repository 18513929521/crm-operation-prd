# CRM运营平台 - 前端系统架构文档

## 1. 概述

本文档描述了CRM运营平台前端的整体架构设计和核心技术栈。

### 1.1 产品层级

```
平台 (Platform)
  └── 应用 (Application)
      └── 功能 (Feature)
          └── 操作 (Operation)
```

**当前平台：** CRM运营平台（CRM Operation Platform）

**架构原则：** 一个应用对应一个微服务 + 一个数据库 + 一个微前端

## 2. 核心技术栈

### 2.1 开发语言与框架

- **Node.js 16+**：JavaScript运行环境
- **Vue 3.3+**：前端核心框架，采用Composition API
- **Vite 4.4+**：构建工具，提供快速的开发体验
- **qiankun 2.10+**：微前端框架，实现主子应用集成
- **TypeScript 5.0+**：类型安全的JavaScript超集（推荐使用）

### 2.2 UI组件与样式

- **Element Plus 2.3+**：企业级UI组件库
- **@element-plus/icons-vue 2.1+**：Element Plus图标库
- **Less 4.2+**：CSS预处理器，提供更强大的样式编写能力

### 2.3 状态管理与路由

- **Vue Router 4.2+**：Vue官方路由管理库
- **Pinia 2.1+**：新一代Vue状态管理库，替代Vuex

### 2.4 HTTP客户端

- **Axios 1.5+**：基于Promise的HTTP客户端

### 2.5 开发工具链

- **ESLint 8.49+**：代码质量检查工具
- **Prettier 3.0+**：代码格式化工具
- **pnpm 8.0+**：快速、节省磁盘空间的包管理器

### 2.6 DevOps工具链

- **Docker 24.x**：容器化技术，应用打包与部署
- **Nginx 1.20+**：Web服务器，用于静态资源托管和反向代理
- **Jenkins 2.x**：持续集成/持续部署（CI/CD）

**架构说明：**
- 主应用负责整体布局、路由管理、认证鉴权、全局状态管理
- 每个微前端应用独立开发、独立部署、独立运行
- 通过qiankun框架实现微前端应用的加载和通信
- 每个微前端应用对应一个后端微服务

### 3.2 主应用职责

#### 3.2.1 核心功能

1. **布局管理（Layout）**
   - 顶部导航栏（Logo、用户信息、退出）
   - 侧边菜单栏（动态菜单渲染）
   - 主内容区（微应用容器）
   - 面包屑导航

2. **路由管理（Router）**
   - 主应用路由配置
   - 微应用路由注册
   - 路由守卫（权限校验）
   - 路由缓存策略

3. **认证鉴权（Auth）**
   - 用户登录/登出
   - Token管理（存储、刷新、失效处理）
   - 权限验证（菜单权限、按钮权限）
   - 会话管理

4. **全局状态（Global State）**
   - 用户信息
   - 权限列表
   - 菜单配置
   - 应用配置

5. **公共组件（Shared Components）**
   - 表格组件
   - 表单组件
   - 对话框组件
   - 确认框组件
   - 通知组件

### 3.5 通信机制

#### 3.5.1 主应用与微应用通信

**1. Props传递（主应用 → 微应用）**

```javascript
// 主应用：注册微应用时传递props
registerMicroApps([
  {
    name: 'tenant-management',
    entry: '//localhost:5175',
    container: '#micro-app-container',
    activeRule: '/tenant',
    props: {
      // 传递给微应用的数据
      user: userInfo,
      permissions: permissionList,
      token: authToken
    }
  }
]);

// 微应用：接收props
export async function mount(props) {
  const { user, permissions, token } = props;
  // 使用传递的数据
}
```

**2. 全局状态（initGlobalState）**

```javascript
// 主应用：初始化全局状态
import { initGlobalState } from 'qiankun';

const actions = initGlobalState({
  user: null,
  permissions: [],
  token: ''
});

// 监听状态变化
actions.onGlobalStateChange((state, prev) => {
  console.log('状态变化', state, prev);
});

// 更新状态
actions.setGlobalState({ user: newUser });

// 微应用：使用全局状态
export async function mount(props) {
  props.onGlobalStateChange((state, prev) => {
    // 监听状态变化
  });
  
  props.setGlobalState({ token: 'new-token' });
}
```

**3. 自定义事件总线**

```javascript
// shared/utils/event-bus.js
class EventBus {
  constructor() {
    this.events = {};
  }
  
  on(event, callback) {
    if (!this.events[event]) {
      this.events[event] = [];
    }
    this.events[event].push(callback);
  }
  
  emit(event, data) {
    if (this.events[event]) {
      this.events[event].forEach(callback => callback(data));
    }
  }
  
  off(event, callback) {
    if (this.events[event]) {
      this.events[event] = this.events[event].filter(cb => cb !== callback);
    }
  }
}

export default new EventBus();
```

#### 3.5.2 微应用间通信

微应用间不直接通信，通过主应用的全局状态进行数据共享：

```
微应用A → 更新全局状态 → 主应用 → 通知微应用B
```

#### 3.7.4 缓存策略

```javascript
// API请求缓存
const apiCache = new Map();

export const request = async (url, options) => {
  const cacheKey = `${url}_${JSON.stringify(options)}`;
  
  if (apiCache.has(cacheKey)) {
    return apiCache.get(cacheKey);
  }
  
  const result = await axios(url, options);
  apiCache.set(cacheKey, result);
  
  // 5分钟后清除缓存
  setTimeout(() => {
    apiCache.delete(cacheKey);
  }, 5 * 60 * 1000);
  
  return result;
};
```

```
Nginx反向代理：

- 微应用2：https://operation.example.com/tenant/
- ...
```

#### 4.2.1 Nginx配置示例

```nginx
server {
    listen 80;
    server_name operation.example.com;
    
    # 主应用
    location / {
        root /usr/share/nginx/html/main-app;
        try_files $uri $uri/ /index.html;
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }
    
    # 微应用：系统管理（system-management）
    location /system {
        alias /usr/share/nginx/html/operation-system;
        try_files $uri $uri/ /system/index.html;
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }
    
    # 微应用：租户管理
    location /tenant {
        alias /usr/share/nginx/html/tenant-management;
        try_files $uri $uri/ /tenant/index.html;
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }
    
    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
    
    # API反向代理
    location /api/ {
        proxy_pass http://backend-gateway:18100/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### 4.3 Docker容器化部署

#### 4.3.1 Dockerfile示例

```dockerfile
# 构建阶段
FROM node:16-alpine as builder

WORKDIR /app

# 安装pnpm
RUN npm install -g pnpm

# 复制依赖文件
COPY package.json pnpm-lock.yaml pnpm-workspace.yaml ./
COPY main-app/package.json ./main-app/
COPY micro-apps/*/package.json ./micro-apps/
COPY shared/package.json ./shared/

# 安装依赖
RUN pnpm install

# 复制源代码
COPY . .

# 构建应用
RUN pnpm run build:all

# 运行阶段
FROM nginx:alpine

# 复制构建产物
COPY --from=builder /app/main-app/dist /usr/share/nginx/html/main-app
COPY --from=builder /app/micro-apps/operation-system/dist /usr/share/nginx/html/operation-system
COPY --from=builder /app/micro-apps/tenant-management/dist /usr/share/nginx/html/tenant-management

COPY nginx.conf /etc/nginx/nginx.conf

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]
```
