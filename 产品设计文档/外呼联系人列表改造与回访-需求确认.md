## 一、先确认一件事：本次「回访」是什么

现有 PRD / 代码里已有 **任务类型 `二次回访`**（XLeads 导入，工作台只有「回访结果 + 备注」）。  
原型里的「回访」**不是这条链路**，而是：

> CC 在 **外呼联系人列表 · 已完成** 上，对已经做过 **定位 / 邀约** 的联系人再次外呼，录入回访结论；接通后进入主管 **质检列表 · 回访外呼**。

| 对比项 | 现有 `task_type = 二次回访` | **本次要做的回访（原型）** |
| --- | --- | --- |
| 谁发起 | XLeads 导入任务 | CC 在联系人列表点「回访」 |
| 类型 | 任务类型「二次回访」 | **回访类型**：定位回访 / 邀约回访（由原任务类型决定） |
| 表单 | 回访结果：满意 / 基本满意 / 不满意 / … | **回访状态** + 拜访信息 + 沟通记录上传 |
| 质检 Tab | 「回访外呼」Tab 已有，但列与定位/邀约完全一样，无回访字段，也未入池 | 专属列：回访类型、回访结果；详情展示回访信息 |

**建议口径（请确认）**：本期只做原型这条「定位回访 / 邀约回访」。现有 `二次回访` 任务类型、工作台旧表单先保留不改；质检「回访外呼」Tab **只展示本期回访入池数据**，不混入 XLeads 二次回访任务。

## 三、业务主流程（建议）

```
定位/邀约外呼完成（公司 finished_flag=1，进入「已完成」）
        ↓
CC 在联系人列表点「回访」
        ↓
打开与「详情」同款抽屉（不跳工作台）
        ↓
点手机号旁图标直接拨号（无状态栏、无拨号前置校验）
        ↓
最底部「回访信息」：回访状态 +（邀约回访）拜访信息 + 沟通记录 → 提交
        ↓
当次 CC 外呼已接通 且 回访状态 ≠ 未接通 → 写入质检池
仅未接通 / 号码异常 → 只落回访记录，不入质检
        ↓
主管在质检列表「回访外呼」点详情/质检（筛选保持现状）
        ↓
回访状态 = 已失效（定位回访）时：提示并同步作废关联拜访（租户端）
```

## 四、外呼联系人列表改造

### 4.1 页面结构

- 标题：外呼联系人列表  
- 副标题：请在此完成您每天的外呼任务  
- **PillTabs**：`待执行` | `已完成`（默认「待执行」）  
- **FilterBar** 两行筛选（控件按字段类型，不使用原型占位文案「请输入公司名称」）  
- 表格上方关键词：搜索公司、联系人、手机号  
- 表格多选保留（本期不做批量操作，与现状一致）  
- 分页保留  

**撤回**：原型操作列只有「详情 / 回访」。建议 **已完成 Tab 仍保留撤回**（现有交付/拜访状态机不变），与「回访」并列。若产品要求严格按原型隐藏撤回，请在文末勾选。

### 4.2 Tab 口径（建议）

完成态在现网是 **公司维度** `call_company.finished_flag`（工作台提交后置 1），不是联系人 `processStatus`（枚举有定义但未落库）。

| Tab | 建议口径 |
| --- | --- |
| 待执行 | 当前 CC 名下，所属公司 `finished_flag = 0`，且撤回状态 ≠ 已撤回 |
| 已完成 | 当前 CC 名下，所属公司 `finished_flag = 1`，且撤回状态 ≠ 已撤回 |

已撤回记录：不进上述两 Tab。原视图「已撤回」本期可去掉，或作为筛选「撤回状态」——默认去掉，与原型一致。

### 4.3 筛选字段

| 字段 | 控件 | 说明 |
| --- | --- | --- |
| 公司名称 | 文本 | 模糊匹配 |
| 手机号 | 文本 | 按脱敏前号码查（CC 界面仍脱敏） |
| 通话状态 | 下拉 | 已接通 / 未接通 / 号码异常 / 通话中（与现网通话状态口径一致，取最新一次） |
| 定位状态 | 下拉 | 正确（`locate_valid=1`）/ 错误（`locate_valid=0`）/ 空 |
| 是否邀约 | 下拉 | 是（存在 `call_invite_info`）/ 否 |
| 最新外呼时间 | 日期范围 | `last_call_time` |
| 拜访时间 | 日期范围 | 取该联系人邀约信息 `visit_time`；无邀约则筛不到 |

### 4.4 列表列

| 列 | 取值 |
| --- | --- |
| 公司名称 | `company_name` |
| 联系人名称 | `name` |
| 手机号 | 脱敏 |
| 最新通话状态 | 最新一次通话；Tag：未接通红、已接通绿 |
| 定位状态 | 正确 / 错误 / `-` |
| 是否邀约 | 是 / 否 |
| 最新外呼时间 | `last_call_time` |
| 操作 | 详情；已完成且允许回访时显示「回访」；撤回按现有规则 |

不单独加「拜访时间」列（仅作筛选），与原型列一致。

### 4.5 「回访」按钮显隐（建议）

同时满足才展示且可点：

1. 当前在 **已完成** Tab  
2. 原任务类型为 **定位** 或 **邀约**（成交不展示）  
3. 未撤回（非审核中、非已撤回）  
4. 定位任务：已填「定位是否有效」；邀约任务：已有完整邀约信息  

不要求必须已质检通过才允许回访（本地已有定位/邀约数据即可）。若必须「质检通过后才能回访」，请在待确认项勾选。

点击「回访」：**打开与「详情」同款抽屉**（不跳转工作台，抽屉内可拨号），见第五节。

「详情」仍打开现有只读抽屉；底部回访信息只读，**同样可用箭头切换历史**（无新增表单、无提交）。

## 五、回访（详情同款抽屉）

### 5.0 交互（已确认）

- **不跳转外呼工作台**。
- 点击「回访」打开抽屉，布局对齐现有「详情」，但 **可拨号、可提交回访**：
  - 组件可复用 `ContactForm`（非整页只读）+ 抽屉壳，`size="92%"`，标题「回访」
  - **不展示坐席状态栏**（不上线 / 暂挂 / 下线）
  - 打开抽屉时初始化外呼 SDK（与工作台 `initCallCenter` 相同），关闭时不强制销毁全局 SDK
  - 公司信息、联系人信息、邀约信息（有则展示）、外呼记录：**只读**
  - 联系人 **手机号旁一键外呼图标**（号码脱敏；服务端带明文拨号）
  - **拨号不做校验**：不校验是否上线、是否绑定坐席、电话条是否就绪、是否按序拨打；图标始终可点，点击即发起外呼。失败仅以中台/SDK 返回提示，前端不预先置灰拦截
  - **最底部「回访信息」模块**：默认可编辑的**新增表单**；卡片右侧提供切换按钮查看历史（见 5.0.1）
  - 页脚：**取消 / 提交**（查看历史时提交仍保存当前新增表单，不改历史）
- 提交只校验**当前新增表单**的回访必填项；**不强制先拨号、不校验当次通话状态**。
- 提交成功后关闭抽屉并刷新列表；不把公司改回「待执行」。**每次提交只 insert 一条新回访，不更新历史记录。**

### 5.0.1 回访模块：新增 vs 历史切换（已确认）

对齐原型卡片右侧圆形箭头。

| 规则 | 说明 |
| --- | --- |
| 每次打开 | 回访模块**始终落在空白新增表单**，不回显上一次填写内容 |
| 新增表单预填 | 仅带出原定位/邀约主数据：回访类型只读；邀约回访的拜访名称/类型/时间/地点/公司/联系人/商机来自原 `call_invite_info`，**不是**上一条回访的改期结果 |
| 切换按钮 | 卡片右侧箭头（或左右箭头）。无历史时置灰/隐藏 |
| 历史浏览 | 按 `create_time` **倒序**逐条只读展示（回访类型、状态、沟通记录、拜访字段、提交时间） |
| 切换不影响草稿 | 从新增切到历史再切回，新增表单已填内容保留在内存，不丢失 |
| 提交 | **始终保存新增表单为新记录**。即使当前画面停在某条历史上，点提交仍 insert 新增那条，**不覆盖、不编辑**历史 |
| 查看历史时 | 历史卡片字段全部 disabled；沟通记录仅可下载预览，不可改文件 |

```
打开回访抽屉
    ↓
回访模块 = 新增空白表单（可编辑）
    ↓
点右侧箭头 → 历史第 1 条（只读）→ 第 2 条 …
    ↓
点回 / 切到「新增」→ 回到当前草稿
    ↓
提交 → INSERT 新增记录 → 关闭抽屉
下次再打开 → 仍是新的空白表单（刚才那条已进入历史）
```

### 5.1 回访类型（只读，系统判定）

| 原任务 `task_type` | 回访类型 |
| --- | --- |
| 定位 | 定位回访 |
| 邀约 | 邀约回访 |

不可手改。同一联系人允许 **多次回访**：每次打开都是新表单，每次提交新增一条，历史通过切换查看。

### 5.2 回访状态（按类型不同）

**定位回访**

| 值 | 说明 |
| --- | --- |
| 已确认 | 定位结论仍有效 |
| 已失效 | 定位/关联拜访作废 |
| 未接通 | 当次未打通；提交后不入质检 |

选「已失效」时，回访类型下方红字：

> 关联的拜访「{拜访名称}」同步失效！

无拜访名称时显示「关联的拜访同步失效！」。提交成功后通知租户端作废对应 `visit_schedule`（无日程则只更新本端回访状态）。

**邀约回访**

| 值 | 说明 |
| --- | --- |
| 已确认 | 拜访仍按约定进行 |
| 需改期 | 需调整拜访时间（提交后应允许改拜访时间） |
| 客户取消 | 客户取消拜访 |
| 未接通 | 当次未打通；提交后不入质检 |

「需改期」时 **拜访时间必填且须晚于原时间**（建议规则，请确认）。

## 六、质检列表「回访外呼」完善

### 6.1 入池条件（回访专属）

须同时满足：

1. 存在一条 **回访提交记录**  
2. 该次回访在抽屉内产生的通话为 **CC 人工外呼且已接通**  
3. **回访状态 ≠ 未接通**（已确认 / 已失效 / 需改期 / 客户取消）  
4. 当前主管数据权限范围内  

入池时机：回访提交成功且当次已接通时写入，状态 `PENDING_QC`，记录质检入库时间。  
同一联系人多次回访：每次满足条件 **单独入质检一条**（建议）。
