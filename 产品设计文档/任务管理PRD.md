# 一、需求背景

合同、订单、任务构成中台交付链路的三层对象：

| 对象 | 本质 | 时间代表什么 |
| --- | --- | --- |
| 合同 | 商业承诺 | 客户购买服务的有效周期 |
| 订单 | 某一项服务交付 | 该服务计划交付周期 |
| 任务 | 执行动作 | 某个具体执行动作的时间安排 |

任务是交付链路的执行层，分为两大类：

- **数据交付任务**：由租户订单自动生成，或由运营手动新建；通过**三步**配置（基础信息 → 数据需求 → 结果交付）圈选交付条件，并**轮询数据库**按条件取数后推送。**不再内嵌数据增强步骤**。
- **Agent 执行任务**：面向单个 Agent 的作业配置；通过**两步**配置（基础信息 → 执行配置）选定 Agent、填写交付数量 / 是否导出 excel 与入参；结果默认**入库**，可选同时导出 Excel。其中**数据增强类 Agent**负责按固定查找数量拉取数据并入库，为交付任务提供数据源。

**协作关系（重点）**

```
数据增强 Agent 执行任务                数据交付任务
─────────────────────                 ─────────────────
按「固定查找数量」执行                  按「数据需求」条件
查到的数据全部入库                     轮询 / 查找数据库
（不要求完全符合最终交付条件）          命中后再按「结果交付」推送
```

**合同 → 订单 → 租户订单任务主链路**（与合同/订单 PRD 一致）：

```
合同「存草稿」     → 仅合同草稿，不生成订单
合同「正式保存」   → 合同锁定不可再改
                   → 每个服务项自动生成 1 条「订单草稿」

订单「草稿编辑」   → 补数据需求 / 交付配置等（按订单可编辑规则）
订单「正式保存」   → 订单锁定不可再改
                   ├─ 服务=寻迹 → 暂不建任务；客户每次寻迹 → 生成 1 条「租户订单-寻迹」任务
                   └─ 服务=推送 → 立刻生成 1 条「租户订单-推送」草稿任务
```

# 二、需求目标

1. 任务管理页按两大类分 Tab：**数据交付任务**、**Agent 执行任务**；两类均可创建、列表筛选与运维。
2. 明确数据交付任务的三种来源展示：**租户订单-寻迹**、**租户订单-推送**、**手动创建**，以及各自的自动生成与字段可编辑规则；租户订单任务的触发以**订单正式保存**为前置。
3. 新增交付任务采用**三步**向导：基础信息（含**交付终点**）→ 数据需求（含**交付数量**）→ 结果交付（**交付周期** / 交付频率 / 频率规则 / 周期交付数量）；目标范围支持条件筛选 / 指定名单；任务执行时**仅轮询数据库**。
4. **数据增强**改为独立的 **Agent 执行任务**：每次按固定查找数量执行，查到的数据**全部入库**（不论是否完全符合最终交付条件），供交付任务轮询取用。
5. 数据交付任务的结果交付支持：原力大后台 / 租户端 / 运营端 CC 工作台，并按终点联动租户名称、CC 账号。
6. 新增执行任务采用**两步**向导：基础信息（含选 Agent、**交付数量**、**是否导出 excel**）→ 执行配置（Agent 入参）；列表型入参支持逗号输入与文件上传；结果默认入库，导出 Excel 由「是否导出 excel」控制。
7. 提供列表筛选、进度查看与运维操作；**订单暂停/关闭级联租户订单任务**。

# 三、名词解释

| 名词 | 定义描述 |
| --- | --- |
| 数据交付任务 | 面向线索/数据交付的任务类型 |
| Agent 执行任务 | 针对**单个 Agent** 的执行型任务：基础信息（含 Agent / 交付数量 / 是否导出 excel）→ 执行配置（入参） |
| 执行配置 | 执行任务 Step 2：按所选 Agent 的 schema 动态展示入参表单 |
| 列表型入参 | Agent 入参的一种类型：支持英文逗号分隔手输，或通过上传按钮导入文件 |
| 是否导出 excel | 执行任务基础信息字段：是 / 否；为「是」时额外导出 Excel；为「否」时仅入库 |
| 入库（rawdata） | 执行任务默认结果落库方式；查到的数据写入库，供数据交付任务轮询 |
| 租户订单任务 | 为某个订单服务的数据交付任务；关联订单 ID 非空 |
| 手动创建任务 | 运营通过「新增交付任务」→「交付任务」手工配置的数据交付任务；不计入租户订单交付量 |
| 任务来源 | 仅数据交付任务列表使用：**租户订单-寻迹** / **租户订单-推送** / **手动创建** |
| 寻迹模式 | 合同/订单约定的交付模式；**订单正式保存后**，客户每次在客户端寻迹，系统自动生成一条任务；来源 = 租户订单-寻迹 |
| 推送模式 | 合同/订单约定的交付模式；**订单正式保存时**立刻自动生成一条草稿任务；来源 = 租户订单-推送 |
| 目标范围 | 线索圈选方式：**条件筛选** / **指定名单**（指定名单本期针对 To B） |
| 指定名单 | 上传公司列表，规定本次要查找的公司集合；选定后公司信息写死为该名单；上传后系统解析并展示条数（如「共 200 条数据」），作为交付数量上限 |
| 目标范围数据量 | 指定名单解析后的有效行数 N；交付数量不得超过 N |
| 数据需求 | 数据交付任务中圈选交付对象的条件：目标范围、触达程度、业务/公司/联系人信息等；执行时据此**轮询数据库** |
| 数据增强 | **不再属于数据交付任务步骤**；由独立的 **Agent 执行任务**（选数据增强类 Agent）完成：按固定查找数量拉取，结果入库 |
| 固定查找数量 | 数据增强类 Agent 执行任务每次执行时的查找/拉取上限；查满或查尽即止，**全部写入库** |
| 结果交付 | 配置调度节奏：交付周期、交付频率、频率规则、周期交付数量（交付终点、交付数量已前移至前两步） |
| 交付周期 | 结果交付主字段：**实时交付 / 一次性交付 / 周期性交付**；选后联动后续字段显隐 |
| 交付频率 | 周期性交付下的节奏：每天 / 每周 / 每月 / 自定义 |
| 频率规则 | 随「交付频率」变化的具体排期（如每周 →「周五 18:00」；每月 →「每月 1 日 09:00」或「每月最后一天」） |
| 周期交付数量 | 每个频率触发节点单次交付的条数（如 20 条） |
| 交付终点（数据交付） | 原力大后台 / 租户端 / 运营端 CC 工作台（配置位置：**基础信息**） |
| 交付终点（执行任务） | 默认**入库**；是否额外导出 Excel 由「是否导出 excel」控制（不再多选 rawdata/excel） |

# 四、功能设计

## （一）任务分类总览

```
任务
├── 数据交付任务
│   ├── 租户订单-寻迹     （订单正式保存后，客户端每次寻迹 → 自动生成任务）
│   ├── 租户订单-推送     （订单正式保存时 → 自动生成草稿任务）
│   └── 手动创建          ← 「新增」→ 交付任务
└── Agent 执行任务         ← 「新增」→ 执行任务；单 Agent **两步**配置
```

**两大类对比**

| 维度 | 数据交付任务 | Agent 执行任务 |
| --- | --- | --- |
| 入口 | 「新增」→ 交付任务；或由订单驱动自动生成 | 「新增」→ 执行任务 |
| 步骤 | **三步**：基础信息 → 数据需求 → 结果交付 | **两步**：基础信息 → 执行配置 |
| 核心职责 | 按数据需求**轮询数据库**并交付 | 执行单个 Agent；**数据增强类**按固定量查找并**入库** |
| Agent | **不配置** Agent | **仅配置 1 个** Agent |
| 交付 / 产出 | 原力大后台 / 租户端 / 运营端 CC 工作台 | 默认入库；可选导出 Excel（「是否导出 excel」） |
| 与订单关系 | 可关联订单（寻迹/推送）或不关联（手动） | 一般不关联订单 |

**数据交付任务 · 三种来源**

| 维度 | 租户订单-寻迹 | 租户订单-推送 | 手动创建 |
| --- | --- | --- | --- |
| 前置条件 | 对应订单已**正式保存**且处于可运行态 | 对应订单**正式保存**当刻 | 无 |
| 触发时机 | 客户每次在客户端寻迹一次 | 订单正式保存成功 | 运营点击「新增」→ 交付任务 |
| 初始状态 | 按系统策略进入待执行/执行中（以实际上线为准） | **草稿** | 完成创建后进入待执行；亦可先存草稿（若上线） |
| 关联订单 | 有 | 有 | 无（关联订单 id 展示为 `-`） |
| 参数来源 | 订单规定字段 + 客户寻迹时额外增加的条件 | 订单规定规则预填 | 全部空白，运营自填 |
| 可编辑范围 | 见「寻迹模式」专节 | 仅基础信息部分字段可编辑 | **三个模块**全部可编辑 |
| 草稿删除 | — | **不可删除**（只能编辑） | **可删除** |
| 是否计入订单交付量 | 是 | 是 | **否**（可推到租户端，但不计入该租户订单） |
| 受订单暂停/关闭级联 | **是** | **是** | 否 |

## （二）数据交付任务 · 对象设计

### 1. 对象结构（三步配置）

与原型「新增交付任务」弹窗一致：

| 步骤 | 模块 | 作用 |
| --- | --- | --- |
| Step 1 | 基础信息 | 任务名称、**交付终点**、预期执行时间、优先级、备注 |
| Step 2 | 数据需求 | **交付数量**、目标范围、触达程度、业务信息 / 指定名单、公司信息、联系人信息（执行时据此轮询库） |
| Step 3 | 结果交付 | **交付周期**、**交付频率**、**频率规则**、**周期交付数量** |

> **数据增强不在本向导内**：需单独创建「Agent 执行任务」并选择数据增强类 Agent，将数据写入库后，本任务再轮询取数。

### 2. 对象核心字段

| 字段 | 说明 |
| --- | --- |
| `task_id` | 任务 ID，系统自动生成（如 JOB2025120001） |
| `task_name` | 任务名称 |
| `task_category` | 任务大类：数据交付任务 / Agent 执行任务 |
| `task_source` | 任务来源：**租户订单-寻迹** / **租户订单-推送** / **手动创建**（列表直接展示该三值） |
| `order_id` | 关联订单 ID；手动创建任务为空 |
| `target_scope` | 目标范围：条件筛选 / 指定名单 |
| `priority` | 优先级：高 / 中 / 低（或数值，以实际上线为准） |
| `expected_exec_at` | 预期执行时间 |
| `remark` | 备注 |
| `delivery_progress` | 已交付 / 需求（如 107/300） |
| `delivery_endpoint` | 交付终点 |
| `task_status` | 见「任务生命周期」 |
| `created_at` / `updated_at` | 创建、更新时间 |

### 3. 执行语义：轮询数据库

数据交付任务进入执行后：

1. 读取本任务「数据需求」条件（条件筛选或指定名单 + 联系人条件等）。  
2. **轮询 / 查询数据库**中已入库的数据（库内数据来源含数据增强 Agent 执行任务写入的结果，以及其他已入库线索）。  
3. 命中且满足交付条件的数据，按「基础信息」中的交付终点，以及「结果交付」中的频率节奏推送。  
4. **本任务不调用增强 Agent**，也不在执行过程中外采补数。  

> 若库中暂无可命中数据，任务可处于等待 / 持续轮询态（间隔与超时策略以实际上线为准），依赖增强任务持续补库。

## （三）创建与分流规则

> 租户订单类任务的创建，必须落在「订单已正式保存」之后；订单仍为草稿时，既不因寻迹落任务，也不生成推送草稿任务。

### 1. 寻迹模式 · 订单任务

**前置**：关联订单已**正式保存**，且订单状态为待执行 / 执行中（已暂停、已关闭、草稿订单均不可产生新寻迹任务）。

**触发**：客户在客户端每完成一次寻迹，系统自动生成一条数据交付任务；来源 = **租户订单-寻迹**。

**参数填充**

- 任务中参数自动填充为：订单已规定的字段 + 客户本次寻迹额外增加的条件。
- 关联订单、任务来源由系统写入。

**结果交付 / 数量与终点（本模式特例）**

| 字段所在步 | 字段 | 规则 |
| --- | --- | --- |
| Step 2 · 数据需求 | 交付数量 | = 客户在客户端输入的需求量；**不得超过订单剩余可交付量**（订单限制） |
| Step 1 · 基础信息 | 交付终点 | 由系统策略决定或继承订单；运营侧可不开放改 |
| Step 3 · 结果交付 | 交付频率等 | 固定为 **实时**（或不展示本步）；不配周期字段 |

> 寻迹模式任务的数据需求由订单与客户端寻迹条件共同决定；运营侧以只读或受限编辑为准。执行时同样**仅轮询库**取数。

### 2. 推送模式 · 订单任务

**触发**：**订单正式保存**成功时，系统立刻自动生成一条负责该订单的**草稿**任务；来源 = **租户订单-推送**。  
（订单草稿编辑过程中不生成；合同正式保存只生成订单草稿，不生成本任务。）

**预填与可编辑规则**

| 模块 | 预填来源 | 可编辑性 |
| --- | --- | --- |
| 基础信息 · 任务名称等身份字段 | 可由系统按订单默认生成 | 按实际上线；至少支持展示 |
| 基础信息 · 交付终点 | 按订单规定预填 | **不可修改**（或按实际上线只读） |
| 基础信息 · 预期执行时间 | 空或默认 | **可编辑** |
| 基础信息 · 优先级 | 空或默认 | **可编辑** |
| 基础信息 · 备注 | 空 | **可编辑** |
| 数据需求（含交付数量） | 完全按订单规定的规则预填 | **不可修改、不可增加** |
| 结果交付（交付频率等） | 完全按订单规定预填 | **不可修改、不可增加** |

**删除限制（重点）**

- 订单自动创建的 **「租户订单-推送」** 任务：**禁止删除**（含草稿态）；列表草稿行**仅展示「编辑」**，无「删除」。
- 只能编辑草稿中的可编辑字段（**基础信息部分字段**），确认后进入执行链路。
- 若订单交付依赖库内增强数据，需另行配置 / 调度 **数据增强 Agent 执行任务** 补库（不在推送任务表单内配置）。

### 3. 手动创建任务

**入口**：任务列表页右上角「新增交付任务」下拉 → **交付任务** → 打开「新增交付任务」弹窗。

**规则**

- 统一归类为**手动创建任务**，`task_source = 手动创建`，无关联订单（关联订单 id 展示为 `-`）。
- **三个模块**均无线索、全部空白，由运营从零配置。
- 结果可推送到租户端，但**不计入该租户任一订单的交付量**。
- **草稿可删除**：右上角新建产生的手动任务，若保存为草稿，列表展示 **「编辑」「删除」**；删除后不可恢复（需二次确认）。
- **不受**订单暂停/关闭级联影响。
- 数据源依赖：若库中尚无足够可命中数据，需先（或并行）创建 **数据增强 Agent 执行任务** 向库中补数。

> **草稿删除对照（对齐列表原型）**  
> | 任务来源 | 草稿态操作 |  
> | --- | --- |  
> | 租户订单-推送（订单自动创建） | **仅「编辑」**，无删除 |  
> | 手动创建（右上角「新增交付任务」） | **「编辑」+「删除」** |

**流程**：三步向导 → 取消 / 上一步 / 下一步 / 完成。

- **取消**：关闭弹窗，不保存（或按实际上线提示是否放弃草稿）
- **上一步 / 下一步**：步骤间跳转；需通过当前步必填校验
- **完成**：任务确认创建（进入待执行；若支持存草稿则另有入口）

## （四）三步表单设计

> 新增 / 编辑交付任务为**三步**向导（对齐最新原型）。底部：取消；非首步含「上一步」；非末步含「下一步」；末步为「完成」。

### Step 1 · 基础信息

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 任务名称 | 是 | 文本；占位「请输入作业名称」 |
| 交付终点 | 是 | 下拉：**原力大后台 / 租户端 / 运营端 CC 工作台**；占位「请选择交付终点」 |
| 预期执行时间 | 是 | 日期时间选择 |
| 优先级 | 是 | 下拉：高 / 中 / 低 |
| 备注 | 否 | 文本；占位「请输入备注」 |

**交付终点联动（本步内）**

| 交付终点 | 额外字段 |
| --- | --- |
| 原力大后台 | 无 |
| 租户端 | 出现 **租户名称**（必填，下拉选择具体租户） |
| 运营端 CC 工作台 | 出现 **CC 账号**（必填，下拉选择具体 CC） |

> 手动创建任务选择「租户端」时，数据可推至该租户，但**不写入/不累计**该租户订单的已交付量。

**按来源差异**

| 来源 | 表现 |
| --- | --- |
| 手动创建 | 全部空白可填 |
| 租户订单-推送 | 预期执行时间、优先级、备注可编辑；交付终点等按订单只读继承 |
| 租户订单-寻迹 | 由系统自动填充，运营侧编辑范围受限 |

### Step 2 · 数据需求

> 对齐原型：目标范围、**交付数量**、触达程度，并按目标范围切换模块形态。条件结构与订单侧对齐，便于订单任务只读继承。

#### 1）公共字段

| 字段 / 模块 | 必填 | 说明 |
| --- | --- | --- |
| 目标范围 | 是 | 下拉，枚举仅两项：**条件筛选** / **指定名单** |
| 交付数量 | 是 | 本任务计划交付总条数；见下方「指定名单 · 交付数量校验」 |
| 触达程度 | 是 | 下拉（定位 / 邀约 / 成交等，与订单对齐） |

**指定名单 · 交付数量校验（按任务来源）**

| 任务来源 | 规则 |
| --- | --- |
| **租户订单-推送 / 租户订单-寻迹** | 交付数量等**直接继承订单**；任务侧只读展示 |
| **手动创建** | 若目标范围 = 指定名单且已解析条数 N：交付数量 **`max = N`**；若输入 > N，提示 **「交付数量大于目标范围数据量」** |

手动创建 · 指定名单校验细则：

| 规则 | 说明 |
| --- | --- |
| 解析展示 | 上传后展示「共 N 条数据」 |
| 输入框最大值 | `max = N` |
| 超限提示文案 | **交付数量大于目标范围数据量** |
| 未解析成功 | 建议禁止进入下一步 / 或禁止提交超限的交付数量 |

#### 2）目标范围 = 条件筛选

展示完整可配条件：

| 模块 | 说明 |
| --- | --- |
| 业务信息 | 所属业务线（必填）+ 业务线下团队多选勾选 |
| 公司信息 | 条件构建器：字段 + 规则 + 值；多行以「且」连接；支持增减行（可自由配置公司名称、公司属性等） |
| 联系人信息 | 同公司信息结构的条件构建器 |

**业务信息（示意）**

- 所属业务线：如「销售」
- 选定后展示该业务线下团队 checkbox

**公司信息 / 联系人信息（条件行）**

- 每行：`字段` + `规则` + `值`
- 行间逻辑：且
- 操作：减号删除该行；支持新增条件行

#### 3）目标范围 = 指定名单（本期针对 To B）

> 指定名单规定了本次要查找的**公司列表**。名单一经选定/上传，**公司侧**相关配置全部写死为该名单，不可改为其他公司圈选方式。

**展示模块**

| 模块 | 表现 |
| --- | --- |
| 指定名单上传 | 「下载模版」+ 点击/拖拽上传区；支持 csv / xls；上传成功后解析并展示 **「共 N 条数据」** |
| 公司信息 | **写死、只读**：条件行固定绑定名单字段，不可增删、不可改规则与值 |
| 联系人信息 | 仍可配置联系人侧筛选条件（结构同条件筛选） |
| 业务信息 | 按实际上线：指定名单场景下可不展示，或以订单继承只读为准 |

**上传与解析**

| 步骤 | 说明 |
| --- | --- |
| 上传文件 | 用户上传名单（如 xls） |
| 系统解析 | 统计有效数据行数 N，展示「共 N 条数据」 |
| 写入 | 保存为目标范围数据量 `list_row_count`，供本步「交付数量」校验 |
| 更换名单 | 重新解析 N；若已填交付数量 > 新 N，提示并截断 |

**公司信息 · 写死规则（对齐原型）**

系统自动生成固定条件行（示例），值侧绑定「指定名单-对应列」，控件禁用：

| 字段 | 规则 | 值（只读） |
| --- | --- | --- |
| 公司名称 | 是 | 指定名单-公司名称 |
| 统一社会信用代码 | 是 | 指定名单-统一社会信用代码 |

- 行间逻辑：且
- 不提供「新增条件」；删除按钮不可用或不展示
- 含义：公司范围 = 上传名单中的公司集合，不再用自由条件圈公司

**切换目标范围时**

| 操作 | 处理 |
| --- | --- |
| 条件筛选 → 指定名单 | 清空自由公司条件；展示上传区；公司信息改为写死行 |
| 指定名单 → 条件筛选 | 提示将清除名单、解析条数与写死绑定；公司信息恢复为可编辑条件构建器 |

#### 4）按来源差异

| 来源 | 表现 |
| --- | --- |
| 手动创建 | 可选手动切换目标范围并完整配置（指定名单下公司侧仍写死）；需自行上传并接受条数解析；交付数量可填 |
| 租户订单-推送 | **只读**：目标范围、交付数量、名单及解析条数等**完全继承订单**，不可改、不可增 |
| 租户订单-寻迹 | 订单规定字段 + 客户寻迹额外条件；交付数量来自客户端需求量；以系统写入为准 |

### Step 3 · 结果交付

> 对齐最新原型：本步配置调度节奏——**交付周期**及（周期性下的）交付频率 / 频率规则 / 周期交付数量。交付终点见 Step 1，交付数量见 Step 2。

#### A. 本步字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 交付周期 | 是 | 下拉：**实时交付 / 一次性交付 / 周期性交付**；选后联动后续字段显隐 |
| 交付频率 | 条件必填 | 仅「周期性交付」时展示：每天 / 每周 / 每月 / 自定义 |
| 频率规则 | 条件必填 | 随「交付频率」变化的具体排期，见下方专节；非周期性不展示 |
| 周期交付数量 | 条件必填 | 每个触发节点计划交付的条数；非周期性不展示（一次性以 Step 2 交付数量为准，齐批后一次推送） |

#### A2. 交付周期联动

| 交付周期 | 额外字段 | 执行语义 |
| --- | --- | --- |
| **实时交付** | 无 | 按实时策略交付，不配周期排期 |
| **一次性交付** | **无**（不展示交付时间） | 本批目标数据**全部找到后，立刻统一推送**至交付终点；不以预约时刻触发 |
| **周期性交付** | 交付频率 + 频率规则 + 周期交付数量 | 按频率规则触发节点分批推送 |

#### B. 字段层级与配置示例

```
结果交付
  ├── 交付周期：实时交付 / 一次性交付 / 周期性交付
  └──（仅周期性）
        ├── 交付频率：每天 / 每周 / 每月 / 自定义
        ├── 频率规则：随交付频率变化的具体排期
        └── 周期交付数量：每次触发节点交付条数
```

**完整配置示例（每月推 20 条）**

| 配置项 | 取值 |
| --- | --- |
| Step 2 · 交付数量 | 如 `100`（任务总目标） |
| Step 3 · 交付周期 | **周期性交付** |
| Step 3 · 交付频率 | **每月** |
| Step 3 · 频率规则 | **每月 1 日 09:00**（或「每月最后一天 09:00」） |
| Step 3 · 周期交付数量 | **20** |

含义：每月指定时刻触发一次，每次推 **20 条**，累计达到 Step 2「交付数量」后停止（或任务结束/关闭）。

**完整配置示例（每周）**

| 配置项 | 取值 |
| --- | --- |
| 交付周期 | 周期性交付 |
| 交付频率 | 每周 |
| 频率规则 | **周五 18:00** |
| 周期交付数量 | **500 条** |

**完整配置示例（一次性）**

| 配置项 | 取值 |
| --- | --- |
| Step 2 · 交付数量 | 如 `100`（本批总目标） |
| Step 3 · 交付周期 | **一次性交付** |
| 交付频率 / 频率规则 / 周期交付数量 / 交付时间 | **均不展示、不配置** |

含义：任务执行后持续轮询/查找，待本批数据**全部凑齐**（达到交付数量或判定本批已齐），**立刻一次性推送**至交付终点，不等待用户指定的交付时刻。

#### C. 频率规则明细（按交付频率，仅周期性）

| 交付频率 | 频率规则需配置的内容 | 控件形态（示意） | 频率规则展示 / 示例 |
| --- | --- | --- | --- |
| **每天** | 交付时刻（时:分） | 时间选择器 | `09:00` |
| **每周** | 星期（可多选）+ 交付时刻 | 星期多选 + 时间选择器 | `周五 18:00`；若多选：`周一、周五 18:00` |
| **每月** | 日期策略 + 交付时刻 | 见下方「月末策略」 | `每月 1 日 09:00` / `每月最后一天 09:00` |
| **自定义** | 间隔天数 N + 交付时刻 | 数字 N + 时间选择器 | `每 3 天 09:00` |

**每周 · 频率规则细则**

| 子项 | 必填 | 说明 |
| --- | --- | --- |
| 星期 | 是 | 周一～周日，支持多选；至少选 1 天 |
| 交付时刻 | 是 | 时:分；同一批已选星期共用同一时刻（如均为 18:00） |

**每月 · 月末策略（定稿）**

| 配置方式 | 规则 |
| --- | --- |
| 固定日（1–28） | 每月该日触发；各月长度不影响 |
| **每月最后一天** | 推荐提供独立选项；2 月→28/29，小月→30，大月→31，统一按**当月最后一天**触发 |
| 选 29 / 30 / 31 | 若控件允许选择：小月无该日时，**回退为当月最后一天**（与「每月最后一天」语义一致） |

> 「一个月推 20 条」只依赖 **周期交付数量=20** + **交付频率=每月** + **每月仅 1 个触发点**；月份天数差异只影响触发日落在哪天，不影响当月推送条数。

**周期交付数量**

| 项 | 说明 |
| --- | --- |
| 含义 | 每一个频率规则触发节点，计划交付的条数 |
| 示例 | `20 条` / `500 条` |
| 校验 | 单次量 ≤ 剩余可交付量；多次累计达到 Step 2「交付数量」后不再继续周期调度（订单任务另受订单上限约束） |

#### D. 寻迹模式特例

| 步骤 | 表现 |
| --- | --- |
| Step 1 | 交付终点按系统/订单策略，可不开放改 |
| Step 2 | 仅关注交付数量（客户端需求量，受订单限制）等已写入字段 |
| Step 3 | 交付频率固定为 **实时**，或不展示本步周期字段 |

#### E. 按来源可编辑性汇总

| 来源 | Step 1 | Step 2 | Step 3 |
| --- | --- | --- | --- |
| 手动创建 | 全部可编辑 | 全部可编辑 | 全部可编辑 |
| 租户订单-推送 | 仅预期执行时间、优先级、备注可编；交付终点只读 | **只读** | **只读** |
| 租户订单-寻迹 | 受限 | 交付数量等系统写入 | 实时 / 不展示周期配置 |

## （五）任务生命周期

| 状态 | 说明 |
| --- | --- |
| 草稿 Draft | 已创建未确认；租户订单-推送初始态；手动任务可进入草稿 |
| 待执行 Pending | 已确认，等待执行 |
| 执行中 Running | 正在执行与交付 |
| 已暂停 Paused | 暂停执行，可恢复 |
| 已完成 Completed | 达成交付目标或正常结束 |
| 已关闭 Closed | 人工关闭，生命周期结束 |

**操作矩阵（通用状态能力）**

| 状态 | 详情 | 编辑 | 删除 | 暂停 | 关闭 |
| --- | --- | --- | --- | --- | --- |
| 草稿 | ❌ | ✅ | ⚠️ **按来源**，见下表 | ❌ | ❌ |
| 待执行 | ✅ | ❌（租户订单类配置已锁定/受限） | ❌ | ✅ | ❌ |
| 执行中 | ✅ | ❌ | ❌ | ✅ | ❌ |
| 已暂停 | ✅ | ❌ | ❌ | ❌ | ✅ |
| 已完成 | ✅ | ❌ | ❌ | ❌ | ❌ |
| 已关闭 | ✅ | ❌ | ❌ | ❌ | ❌ |

**草稿删除细则（必须按任务来源区分，对齐列表原型）**

| 任务来源 | 如何产生 | 草稿态列表操作 | 可否删除 |
| --- | --- | --- | --- |
| **租户订单-推送** | 订单正式保存后**系统自动创建** | **仅「编辑」** | ❌ **禁止删除** |
| **手动创建** | 点击右上角「新增交付任务」→ 交付任务后保存的草稿 | **「编辑」「删除」** | ✅ **允许删除** |
| 租户订单-寻迹 | 客户寻迹自动生成（一般不落草稿） | — | 默认不可删 |
| Agent 执行任务 | 「新增」→ 执行任务 | 编辑 / 删除（若支持草稿） | ✅ 允许删除 |

**列表操作示意（数据交付 · 对齐原型）**

| 状态 × 来源 | 操作 |
| --- | --- |
| 已完成（任意来源） | 详情 |
| 执行中 / 待执行 | 详情、暂停 |
| 已暂停 | 详情、关闭 |
| 已关闭 | 详情 |
| 草稿 · **租户订单-推送** | **编辑**（无删除） |
| 草稿 · **手动创建** | **编辑、删除** |

**交互要点**

- 暂停：停止后续调度与新作业；已在跑作业是否中断由作业侧策略决定
- 关闭：进入终态，不再执行、不再交付（多用于已暂停后的终态操作）
- **推送自动任务与手动任务的本质差异**：推送任务绑定订单交付承诺，草稿只能补齐后执行、不能删；手动任务无订单约束，草稿可删

### 订单生命周期 → 租户订单任务级联

> 仅作用于 `task_source ∈ {租户订单-寻迹, 租户订单-推送}` 且 `order_id` 命中的任务。手动创建、Agent 执行任务不级联。

| 订单操作 | 新任务 | 已有租户订单任务 |
| --- | --- | --- |
| **暂停** | 禁止再生成（寻迹接口应拒绝或提示不可用） | 待执行 / 执行中 → **暂停**；推送草稿不可确认上线（或一并视为冻结） |
| **恢复** | 恢复允许生成 | 因本订单暂停而被暂停的任务 → **恢复** |
| **关闭** | 永久禁止再生成 | 非终态（含推送草稿）→ **关闭**；已完成保持已完成 |

## （六）Agent 执行任务

> 执行任务针对 **一个** Agent：在基础信息中选定 Agent、交付数量与是否导出 excel，再在执行配置中按其 schema 填入参。与数据交付任务共用生命周期状态机，但表单、列表字段均独立。
>
> **与数据交付的协作**：数据增强能力通过本类任务实现——选中数据增强类 Agent，按**固定查找数量**（即基础信息「交付数量」）执行，查到的数据**全部入库**；数据交付任务再按自身「数据需求」轮询库取数。二者解耦，可独立创建与调度。

### 1. 对象结构（两步配置）

与原型「新增执行任务」弹窗一致：

| 步骤 | 模块 | 作用 |
| --- | --- | --- |
| Step 1 | 基础信息 | 任务名称、**交付数量**、**是否导出 excel**、预期执行时间、优先级、**Agent**、备注 |
| Step 2 | 执行配置 | 按所选 Agent 动态渲染入参表单；完成后即创建任务 |

> 对齐最新原型：**取消独立「结果交付」步骤**；原交付终点多选改为「是否导出 excel」；交付数量上移至基础信息。

### 2. 对象核心字段

| 字段 | 说明 |
| --- | --- |
| `task_id` | 任务 ID，系统自动生成 |
| `task_name` | 任务名称 |
| `task_category` | 固定为 Agent 执行任务 |
| `agent_id` / `agent_name` | 所选执行 Agent（列表「执行 Agent」列展示） |
| `delivery_qty` | 交付数量；数据增强场景即**固定查找数量** |
| `export_excel` | 是否导出 excel：是 / 否 |
| `priority` | 优先级 |
| `expected_exec_at` | 预期执行时间 |
| `remark` | 备注 |
| `input_params` | 执行配置入参（JSON / 按 schema 存储；列表型可含手输值或上传文件引用） |
| `delivery_progress` | 已交付 / 需求 |
| `task_status` | 同生命周期枚举 |
| `created_at` / `completed_at` | 创建时间、完成时间 |

### 3. 创建入口与流程

**入口**：任务列表页右上角「新增交付任务」下拉 → **执行任务** → 打开「新增执行任务」弹窗。

**流程**：两步向导 → 取消 / 上一步 / 下一步 / 完成。

- **取消**：关闭弹窗，不保存（或提示是否放弃）
- **上一步 / 下一步**：需通过当前步必填校验
- **完成**：在 Step 2 确认创建，进入待执行（若支持存草稿则草稿可删）
- **切换 Agent**（Step 1）：若 Step 2 已有入参，需二次确认后清空执行配置

> 原型 Step 2 底部若仍显示「下一步」，实现上应改为 **「完成」**（本向导仅两步）。

### 4. 数据增强类 Agent · 专项规则

当所选 Agent 为**数据增强**类（如脉脉商机、销氪爬虫、探迹爬虫、BOSS 爬虫等，以《Agent管理PRD》启用态名录为准）时，额外约定：

| 规则 | 说明 |
| --- | --- |
| 固定查找数量 | Step 1「交付数量」表示**本次查找/拉取上限**（固定值） |
| 入库策略 | 每次执行查到的数据**全部写入库**（默认入库，与「是否导出 excel」无关） |
| 与最终交付条件的关系 | **不要求**查到的数据完全符合某条数据交付任务的最终圈选条件；宽松入库，由交付任务侧再过滤 |
| Agent 状态 | 仅**启用**态 Agent 可供新任务选择；停用后禁止新任务进入，已有任务继续执行（见《Agent管理PRD》） |
| 与交付任务关系 | **无强绑定**：增强任务与交付任务可独立创建；交付任务不内嵌增强配置 |

**推荐配置示意**

- 是否导出 excel：按运营是否需要额外 Excel 文件选择；**入库始终发生**  
- 入参：按该 Agent schema 配置（公司名称列表、地区、行业、关键词等）

##### 列表型入参（重点）

适用场景：入参值为多个条目的列表（如公司名称列表）。

**交互形态（对齐原型）**

1. **手输模式**
   - 用户直接输入，例如：`阿里巴巴, 字节跳动`
   - 解析规则：按**英文逗号** `,` 分隔为列表项；首尾空格 trim

2. **上传入口**
   - 输入框**右侧常驻上传图标按钮**
   - 点击后弹出「上传文件」子弹窗（浮层）

3. **上传文件弹窗**
   - 标题：上传文件
   - 提示：请先下载文件模板，使用文件模板上传数据
   - 「文件模板」链接：下载标准模板
   - 上传区：点击或拖拽文件到此区域进行上传；仅支持导入模板文件格式
   - 底部：取消 / 确认

4. **上传成功后的输入框态**
   - 输入框内展示**文件标签（chip）**：如 `文件.excel`，右侧带 **×** 可移除
   - 不再显示手输文本；表示该列表入参取值来自上传文件内容
   - 输入框右侧**上传图标仍保留**，可重新上传覆盖
   - 点击标签上的 ×：清除文件，恢复为空的手输态

**手输与上传互斥约定**

| 当前态 | 再操作 | 结果 |
| --- | --- | --- |
| 已手输文本 | 确认上传文件 | 以文件为准，覆盖手输内容，切换为文件标签态 |
| 已上传文件 | 点 × 清除 | 恢复空手输态 |
| 已上传文件 | 再次上传并确认 | 替换为新文件标签 |

> 校验：列表型必填时，手输至少 1 个有效项，或已成功绑定上传文件，二者满足其一即可。

# 六、规则对照速查

### 1. 数据交付 · 三种创建路径与任务来源展示

| 路径 | 入口 / 触发 | 任务来源（列表展示） | 计入订单 |
| --- | --- | --- | --- |
| 寻迹自动生成 | 订单已正式保存 + 客户端寻迹事件 | **租户订单-寻迹** | 是 |
| 推送自动生成 | **订单正式保存**当刻 | **租户订单-推送** | 是 |
| 手动新建 | 「新增」→ 交付任务 | **手动创建** | 否 |

### 1b. 合同 → 订单 → 任务主链路速查

| 步骤 | 结果 |
| --- | --- |
| 合同存草稿 | 无订单、无任务 |
| 合同正式保存 | 合同锁定；每服务项 → 1 订单草稿；无任务 |
| 订单草稿编辑 | 补配置；仍无任务 |
| 订单正式保存 + 寻迹服务 | 订单锁定；**暂不建任务**；之后每次寻迹 → 1 条寻迹任务 |
| 订单正式保存 + 推送服务 | 订单锁定；**立刻** 1 条推送草稿任务 |

### 2. 数据交付 · 推送 vs 手动 · 编辑与删除

| 模块 / 能力 | 租户订单-推送（订单自动创建） | 手动创建（右上角新建） |
| --- | --- | --- |
| 基础信息 · 预期执行时间、优先级、备注 | ✅ | ✅ |
| 基础信息 · 交付终点 | ❌ 只读（继承订单） | ✅ |
| 数据需求（含交付数量、目标范围等） | ❌ 只读 | ✅ |
| 结果交付（交付频率 / 频率规则 / 周期交付数量） | ❌ 只读 | ✅ |
| **草稿删除** | ❌ **不可删**，列表仅「编辑」 | ✅ **可删**，列表「编辑+删除」 |

> 数据增强不在交付任务内配置；需另建 Agent 执行任务补库。

### 3. 数据交付 · 目标范围与交付数量（均在 Step 2）

| 选项 | 含义 | 公司信息 | 交付数量 |
| --- | --- | --- | --- |
| 条件筛选 | 用条件圈选公司/线索，执行时**轮询库** | 可编辑条件构建器 | 无名单条数上限（订单任务另受订单剩余量等约束） |
| 指定名单（To B） | 上传公司列表，执行时按名单+条件**轮询库** | **写死**为指定名单字段 | 解析「共 N 条」；**手动任务** max=N，超限提示「交付数量大于目标范围数据量」；**租户订单任务**继承订单 |

> 指定名单下，Step 2 **联系人信息**条件仍可配置，不随公司名单写死。

### 3b. 增强入库 × 交付轮询（协作速查）

| 任务 | 做什么 | 不做 |
