# CRM工作流引擎产品需求文档

> **核心设计理念**：用生命周期阶段跟踪业务宏观进展，用工作流管理具体执行细节，二者协同工作，为不同角色提供所需视图。

> **实施策略**：首期通过后端工作流引擎实现核心业务流程的灵活配置，通过售前沟通为租户定制化配置，为未来前端可视化配置预留扩展空间。

## 术语表

| 术语 | 英文 | 定义 |
|------|------|------|
| **生命周期阶段** | Lifecycle Stage | 描述商机/线索在销售过程中的宏观进展状态，用于跟踪、分析和预测，如"初步接触"、"需求确认"、"成功约见" |
| **工作流** | Workflow | 每个生命周期阶段的具体执行流程，包含任务清单、必填字段、审批规则等，指导执行者完成具体操作 |
| **阶段流转** | Stage Transition | 商机/线索从一个生命周期阶段推进到下一个阶段的过程，可基于条件自动流转或手动推进 |
| **流转条件** | Transition Condition | 触发阶段流转的业务规则，如字段完成度≥100%、评分≥3分等 |
| **租户** | Tenant | 使用系统的独立企业客户，每个租户拥有独立的数据和配置空间 |
| **工作流引擎** | Workflow Engine | 后端核心组件，负责解析配置、执行流转规则、管理状态变更等 |
| **配置模板** | Configuration Template | 预定义的行业最佳实践流程配置，用于快速初始化租户配置 |
| **必填字段** | Required Field | 在特定阶段必须填写的字段，通常作为流转条件的一部分 |
| **业务规则引擎** | Business Rule Engine | 执行字段验证、条件判断、自动计算等业务逻辑的核心组件 |
| **Leads** | Leads | 潜在销售线索，尚未转化为商机的初步联系对象 |
| **商机** | Opportunity / PPL | 已确认有明确需求和购买意向的销售机会（PPL = Pipeline） |
| **赢单概率** | Win Probability | 每个生命周期阶段对应的预估成交概率，用于销售预测 |
| **销售漏斗** | Sales Funnel | 展示销售各阶段分布和转化情况的可视化视图 |
| **报价阶段** | Quotation Stage | 销售流程中提供正式报价的特定阶段，每个流程有且仅有一个 |
| **字段联动** | Field Dependency | 字段之间的关联关系，如某字段值变化触发其他字段显示或计算 |
| **自动化规则** | Automation Rule | 基于特定触发条件自动执行的动作，如自动分配、自动通知等 |

## 1. 产品概述

### 1.1 产品愿景
打造灵活可配置的CRM工作流引擎，通过后端配置能力支持不同企业的差异化销售流程，为未来自助配置奠定基础。

### 1.2 要解决的问题
- **业务流程僵化**：传统CRM强制所有客户使用相同的销售流程
- **定制成本高**：每个客户需求都要重新开发，交付周期长
- **扩展性差**：缺乏统一的流程引擎，后续优化困难

### 1.3 核心价值
- **对销售团队**：获得符合自身业务特点的销售流程
- **对管理者**：清晰的流程管控和数据沉淀
- **对企业**：快速交付定制化流程，为未来自助配置预留空间

## 2. 用户角色与核心需求

### 2.1 售前顾问/实施工程师
**核心需求**：快速为客户配置定制化流程
- 理解客户业务需求，梳理销售流程
- 通过配置文件或管理后台完成流程定制
- 为不同业务线配置差异化流程
- 验证配置正确性和完整性

### 2.2 销售总监
**核心需求**：清晰掌握销售进展，精准预测业绩
- 直观的销售漏斗视图
- 关键节点的自动提醒
- 销售过程的透明化管理

### 2.3 销售代表
**核心需求**：简单高效地完成日常工作
- 清晰的任务指引
- 减少重复信息填写
- 移动端友好体验

### 2.4 系统管理员
**核心需求**：安全稳定的系统管理
- 多租户数据隔离
- 配置权限管理
- 系统性能监控

## 3. 核心功能详述

### 3.1 后端工作流引擎

#### 3.1.1 工作流配置能力
**功能描述**：基于配置文件或管理后台定义销售阶段和流转规则

**用户场景**：
- 售前工程师根据客户需求配置销售流程
- 实施工程师调整阶段顺序和流转条件

**关键特性**：
- 支持JSON/YAML格式的流程配置文件
- 定义销售阶段名称、顺序、预计完成时间
- 标记报价阶段（每个流程有且只有一个）
- 配置阶段间的流转条件和自动推进规则
- 配置验证和错误提示机制

#### 3.1.2 流程模板库
**功能描述**：提供各行业最佳实践模板，快速启动配置

**用户场景**：
- 新客户入驻时售前选择行业模板快速初始化
- 参考其他企业的优秀流程设计

**关键特性**：
- 按行业分类的流程模板（SaaS、制造、咨询等）
- 预定义的配置模板文件
- 模板复制和自定义修改能力
- 配置文档和说明

### 3.2 字段与表单配置

#### 3.2.1 阶段字段配置
**功能描述**：为每个销售阶段配置所需的字段和表单

**用户场景**：
- 为"需求分析"阶段配置客户信息收集字段
- 为"报价审批"阶段配置审批必填字段

**关键特性**：
- 通过配置定义每个阶段的必填/可选字段
- 字段显示顺序和分组配置
- 字段验证规则配置
- 基于角色的字段可见性控制

#### 3.2.2 标准界面模板（后续扩展）
**功能描述**：提供标准化的界面布局，首期使用预设模板

| 模板类型 | 适用场景 | 实现方式 |
|---------|---------|---------|
| 详情工作台 | 客户信息管理 | 前端固定布局 + 后端字段配置 |
| 任务执行页 | 阶段任务完成 | 前端固定布局 + 后端任务配置 |
| 数据分析页 | 销售数据分析 | 前端固定组件 + 后端数据源 |
| 审批处理页 | 报价合同审批 | 前端固定流程 + 后端审批规则 |

> **备注**：首期采用前端预设模板+后端配置的方式，为未来可视化设计预留接口

### 3.3 灵活字段管理系统

#### 3.3.1 字段类型库
**功能描述**：支持多种字段类型，满足不同业务需求

**字段类型清单**：
- **基础信息**：文本、数字、日期、单选、多选
- **业务数据**：金额、百分比、评分、等级
- **关联信息**：客户关联、产品关联、合同关联
- **计算字段**：自动计算金额、比率、得分

#### 3.3.2 字段业务规则
**功能描述**：为字段配置验证规则和显示逻辑

**用户场景**：
- 大客户需要填写更多信息时显示额外字段
- 特定产品类型需要特定的技术参数字段

**关键特性**：
- 字段必填/选填设置
- 数值范围验证
- 条件显示规则（满足条件时才显示）
- 自动计算规则

### 3.4 阶段感知的工作界面

#### 3.4.1 阶段驱动的界面展示
**功能描述**：根据当前销售阶段自动加载对应的字段和任务

**用户场景**：
- 销售代表进入"初步接触"阶段时，看到联系字段和任务
- 进入"需求分析"阶段时，自动加载需求收集字段

**关键特性**：
- 后端根据当前阶段返回对应的字段配置
- 前端基于配置动态渲染表单和界面
- 阶段进度可视化展示
- 下一阶段流转条件提示

#### 3.4.2 业务规则引擎
**功能描述**：基于配置的业务规则自动化处理流程

**用户场景**：
- 满足条件时自动推进到下一阶段
- 字段验证和数据完整性检查
- 触发自动化任务和通知

**关键特性**：
- 基于规则的阶段流转判断
- 字段联动和自动计算
- 条件触发的自动化动作
- 数据验证和错误提示

### 3.5 生命周期与工作流双层协同

#### 3.5.1 设计理念
**核心思想**：用生命周期阶段跟踪商机的宏观进展，用工作流管理每个阶段的具体执行，二者协同工作。

**双层视图**：
- **生命周期层（宏观视图）**：展示业务进展到哪个阶段，用于跟踪、分析、预测
  - 管理者视角：看整体进度和转化率
  - 呈现形式：看板、销售漏斗、进度条
  
- **工作流层（执行视图）**：展示当前阶段要做什么、怎么做，用于操作和执行
  - 执行者视角：看具体任务和操作指引
  - 呈现形式：任务清单、表单、审批流程

#### 3.5.2 协同机制
**自动联动**：
1. 进入新阶段 → 自动激活对应工作流 → 展示该阶段的界面和任务
2. 完成工作流 → 满足流转条件 → 自动推进到下一阶段

**典型场景**：
```
销售代表李明的一天：
1. 打开系统，看到生命周期看板：15个线索分布在各阶段
2. 点击"王总项目"，当前在"需求确认"阶段
3. 系统自动加载"需求确认"的工作流：
   - 显示任务清单：了解需求、确认预算、识别决策链
   - 显示必填字段：需求描述、预算范围、决策人信息
   - 完成度：60%，还差2个字段未填
4. 李明填完所有字段，点击"完成"
5. 系统自动将线索推进到"成功约见"阶段
6. 自动切换到"成功约见"阶段的工作流界面
```

#### 3.5.3 配置关联
每个生命周期阶段需配置对应的工作流：
- **阶段属性**：名称、顺序、预计时长、赢单概率
- **工作流配置**：任务清单、必填字段、审批规则、界面布局
- **流转条件**：何时可以进入下一阶段（如：必填字段100%完成）

**示例**：
| 生命周期阶段 | 配置的工作流 | 流转条件 |
|-------------|------------|---------|
| 初步联系 | 联系方式配置、沟通记录表单 | 完成3次联系尝试 |
| 需求确认 | 需求调研问卷、预算确认表单 | 合格线索评分≥3分 |
| 成功约见 | 会议准备清单、约见确认表单 | 确认会议时间和参会人 |

#### 3.5.4 价值体现
**对管理者**：
- 通过生命周期看板，一眼看清所有商机的宏观进展
- 通过漏斗分析，发现流程瓶颈和优化机会

**对执行者**：
- 通过工作流指引，清楚知道每个阶段要做什么
- 减少遗漏，提升执行效率

**对系统**：
- 生命周期数据用于业绩预测和统计分析
- 工作流数据用于流程优化和最佳实践总结

## 4. 首期核心业务流程设计

> **首期目标**：实现后端可根据客户需求自由定制两个核心业务流程，支持不同企业的差异化配置需求。

### 4.1 Leads管理流程（线索到约见）

**标准流程**：
```
[线索获取] → [初步联系] → [需求确认] → [成功约见]
```

#### 4.1.1 阶段定义

| 阶段 | 定义 | 核心标准 |
|------|------|---------|
| **线索获取** | 从各渠道获取的未被跟进的线索 | 包括但不限于由AgtNovo提供的、租户自主导入的 |
| **初步联系** | 通过各种途径成功联系到联系人 | 包括但不限于邮件往来、电话拨通 |
| **需求确认** | 确认客户有预算、购买意向 | 确认联系人为关键决策人 |
| **成功约见** | 成功邀约关键决策人线上/线下会议沟通 | 明确会议时间、地点和参会人员 |

#### 4.1.2 阶段流转条件

**阶段1：线索获取**
- 到达条件：
  - ✅ 系统接收到新线索（AgtNovo提供、租户导入、API对接等）
  - ✅ 线索基本信息存在（公司名称或联系人至少一项）

**阶段2：初步联系**
- 到达条件：
  - ✅ 销售认领线索（必须）
  - ✅ 基本信息完整度 ≥ 60%（公司名称、联系人、联系方式等核心字段）
  - ✅ 尝试联系次数 ≥ 1（电话、邮件、即时通讯软件）
  - ✅ 存在通话状态记录
  - 🔄 手动流转或自动分配后自动流转
  - ⏰ 或联系尝试次数 ≥ 配置值（如3次），自动失效

**阶段3：需求确认**
- 到达条件：
  - ✅ 存在有效沟通（必须满足以下任一条件）：
    - 电话接通并沟通 ≥ 1次
    - 邮件收到回复 ≥ 1次
    - 微信/WhatsApp等即时通讯工具有效沟通
  - ✅ 必填字段完成度 = 100%（记录沟通内容、时间、方式）
  - ⏰ 或联系尝试次数 ≥ 配置值（如3次），自动失效

**阶段4：成功约见**
- 到达条件：
  - ✅ 必填字段完成度 = 100%：
    - 购买意向已确认
    - 决策人信息已确认
  - ✅ 会议时间已确定
  - ✅ 参会人员已确认（至少包含1位关键决策人）
  - 🔄 手动确认或自动流转

**转化：创建商机**
- 触发条件：
  - ✅ 约见记录创建成功
  - 🔄 自动创建商机并关联到该线索

> **说明**：✅ = 必须满足的条件；⏰ = 时间相关条件；🔄 = 流转方式（手动/自动）

#### 4.1.3 可配置节点

**初步联系阶段**
- **联系方式偏好配置**：
  - 选择主要联系方式（电话/邮件/微信/WhatsApp）
  - 设置联系尝试次数（如：3次未接通自动流转）
  - 配置联系时间窗口（工作日9:00-18:00）
- **自动分配规则配置**：
  - 按行业自动分配销售
  - 按地域自动分配销售
  - 按线索评分分配资深/新人销售
  - 负载均衡规则（平均分配/能力加权）

**需求确认阶段**
- **合格线索标准配置**：
  - 预算范围验证（如：年预算≥10万）
  - 决策权验证（联系人是否为决策者）
  - 时间窗口验证（计划采购时间≤6个月）
  - 需求明确度评分（1-5分，≥3分为合格）
- **必填信息配置**：
  - 公司基本信息（名称、规模、行业）
  - 联系人信息（姓名、职位、联系方式）
  - 业务需求（产品兴趣、痛点、预算）

**成功约见阶段**
- **约见成功标准配置**：
  - 确认约见时间和地点
  - 确认参会人员（对方决策链成员）
  - 会前准备清单完成（方案准备、资料准备）
- **自动化操作配置**：
  - 约见成功后自动创建商机
  - 自动发送会议邀请和提醒
  - 自动同步到销售日历

#### 4.1.4 典型配置差异

**SMB企业配置**（简化流程，快速流转）
- 阶段数量：3个（初步联系 → 需求确认 → 约见）
- 流转时间：每阶段≤2天，总周期≤1周
- 必填字段：最少（10个核心字段）
- 审批流程：无需审批，销售自主推进
- 自动化程度：高（自动分配、自动提醒、自动流转）

**企业级销售配置**（深度流程，精细管理）
- 阶段数量：5-6个（增加"技术评估"、"多层联系"等节点）
- 流转时间：每阶段3-7天，总周期2-4周
- 必填字段：详细（25+字段，包含技术需求、采购流程等）
- 审批流程：需求确认后需主管审核
- 自动化程度：中（关键节点人工确认，辅以自动提醒）

**配置对比表**：

| 配置项 | SMB企业 | 企业级销售 |
|--------|---------|-----------|
| 流程阶段 | 3个 | 5-6个 |
| 总周期 | ≤1周 | 2-4周 |
| 必填字段 | 10个 | 25+个 |
| 审批要求 | 无 | 主管审核 |
| 技术评估 | 不需要 | 必须 |
| 多层联系 | 不需要 | 决策链全覆盖 |

### 4.2 商机管理流程（PPL - 商机到赢单）

**标准流程**：
```
[商机建立] → [需求分析] → [方案演示] → [商务谈判] → [成交]
```

#### 4.2.1 阶段定义

| 阶段 | 定义 | 核心标准 |
|------|------|---------|
| **商机建立** | 销售了解到客户需求和关键联系人 | 可以从线索转化，也可以直接创建 |
| **需求分析** | 和客户进一步沟通需求，了解到更详细的信息 | 明确客户痛点、需求范围、预算范围 |
| **方案演示** | 根据客户的需求，为客户演示方案和提供初版报价 | 完成方案演示，提供初版报价单 |
| **商务谈判** | 基于已经发生的报价沟通新的方案和价格 | 双方就价格、条款、交付等进行协商 |
| **成交** | 与客户成功签订服务合约 | 合同签署完成，进入交付阶段 |

#### 4.2.2 阶段流转条件

**阶段1：商机建立**
- 到达条件：
  - ✅ 从Leads成功约见后自动创建，或销售手动创建新商机
  - ✅ 负责销售已分配

**阶段2：需求分析**
- 到达条件：
  - ✅ 商机基本信息完整度 = 100%：
    - 客户基本信息
    - 关键联系人信息
    - 预计成交时间
  - ✅ 沟通记录 ≥ 1次
  - 🔄 手动流转

**阶段3：方案演示**
- 到达条件：
  - ✅ 需求调研完成度 = 100%：
    - 客户痛点已明确
    - 需求范围已确定
    - 预算范围已确认
  - ✅ 决策链信息完整（决策人、影响人、使用者）
  - ✅ 竞争对手或现有供应商信息已了解
  - 🔄 手动流转或主管审批后流转

**阶段4：商务谈判**
- 到达条件：
  - ✅ 方案演示已完成
  - ✅ 初版报价单&方案材料已上传
  - ✅ 客户反馈已记录
  - 🔄 手动流转

**阶段5：成交**
- 到达条件：
  - ✅ 最终报价已确定
  - ✅ 合同条款已协商一致：
  - ✅ 合同已签署（电子签名或纸质盖章）

> **说明**：✅ = 必须满足的条件；⏰ = 时间相关条件；🔄 = 流转方式（手动/自动）

#### 4.2.3 流程分支支持

**产品类型分支**
- **标准产品路径**：
  - 快速流程：需求确认 → 产品演示 → 报价 → 成交
  - 配置重点：产品功能匹配度、价格套餐选择
  - 所需资源：销售 + 售前支持
  
- **定制解决方案路径**：
  - 深度流程：需求调研 → 方案设计 → 技术评估 → 定制开发评估 → 商务谈判 → 成交
  - 配置重点：定制需求清单、开发工作量评估、交付周期
  - 所需资源：销售 + 售前 + 技术 + 项目经理

**客户等级分支**
- **新客户流程**：
  - 严格验证：资质审核 → 信用评估 → 首单优惠 → 合同条款严格
  - 配置要点：
    - 必填完整工商信息
    - 需要支付首付款（如：50%）
    - 严格验收标准
    - 新客户引导流程
  
- **老客户流程**：
  - 简化流程：需求确认 → 快速报价 → 成交
  - 配置要点：
    - 历史数据自动加载
    - 优先级更高（自动置顶）
    - 更灵活的付款条件
    - 专属客户经理跟进

**分支配置决策树**：
```
商机建立
    │
    ├─ 产品类型判断
    │   ├─ 标准产品 → 快速演示路径
    │   └─ 定制方案 → 深度调研路径
    │
    └─ 客户类型判断
        ├─ 新客户 → 严格验证 + 新客引导
        └─ 老客户 → 简化验证 + 快速通道
```

#### 4.2.5 核心配置能力

**必须支持的配置项**：
1. **阶段定义**：自定义阶段名称、顺序、预计时长
2. **分支条件**：基于字段值自动判断走哪条路径
3. **审批规则**：不同条件下的审批人和审批链
4. **必填字段**：每个阶段的必填信息清单
5. **自动化操作**：阶段流转时的自动化动作
6. **提醒机制**：超时提醒、任务提醒、审批提醒
7. **权限控制**：不同角色在不同阶段的操作权限
