## 二、与现有实现差异（改造对照）

| 维度 | 现有作业管理 (`/job`) | PRD 任务管理 (`/task`) |
| --- | --- | --- |
| 页面 | 单列表 + 「新增作业」 | 双 Tab：**数据交付任务** / **Agent 执行任务** |
| 创建入口 | 单一 4 步向导 | 下拉「新增交付任务」→ 交付任务(3步) / 执行任务(2步) |
| 步骤 | 基础信息 → 作业配置 → **补充策略(工作流)** → 确认 | 交付：基础信息 → 数据需求 → 结果交付；执行：基础信息 → 执行配置 |
| 关联订单 | 无 `order_id` | 租户订单任务关联 `order_id`；展示任务来源三值 |
| 执行模型 | Flowable + 补充工作流 | 交付任务**轮询库**；增强由独立 Agent 执行任务入库 |
| 状态 | 执行中/已完成/暂停/异常/部分完成 | 草稿/待执行/执行中/已暂停/已完成/已关闭 |
| 字段 | `homeworkName`, `customerName`, `deliveryMethod`… | `taskName`, `deliveryEndpoint`, `taskSource`, `orderId`… |

**可复用资产**

| 资产 | 复用方式 |
| --- | --- |
| `JobForm` 条件筛选 / 指定名单 UI | 迁移至 `DeliveryTaskForm` Step 2；条件组改用 `ConditionGroupPanel` |
| `importCompanyExcel` | 复用或封装为任务名单上传 |
| `OrderForm` 交付配置字段 | Step 3 结果交付字段语义与订单 `deliveryCycle/Frequency/...` 对齐 |
| `@shared/components/Table` | 列表页统一组件 |
| `orderRuleApi` / 条件 meta | 公司/联系人条件构建器 |

**废弃 / 移除**

| 资产 | 说明 |
| --- | --- |
| `HomeworkReplenishmentPolicy` / 工作流 Step | 新任务不再配置 |
| `JobForm` Step 3 补充策略 | 移除 |
| 前端 `getHomeworkWorkflowsPage` 调用 | 新任务不再使用 |

## 三、主链路（本期目标）

```
合同正式保存 → 订单草稿
订单正式保存 → 订单锁定（待执行）
               ├─ 寻迹服务：暂不建任务（预留客户端寻迹触发）
               └─ 推送服务：立刻生成 1 条「租户订单-推送」草稿任务

手动创建 → 「新增交付任务」→ 交付任务（三步）→ 待执行/草稿

Agent 执行任务 → 独立创建 → 待执行（数据增强类：固定查找量入库，二期执行）

订单暂停/关闭 → 级联租户订单任务（寻迹/推送）
```
