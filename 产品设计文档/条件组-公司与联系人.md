# 公司与联系人条件组 — 数据结构说明

> 版本：v1.4  
> 适用范围：订单（`t_order`）、数据交付任务（`t_homework_configuration`）  
> 字段对齐：xleads-tools Neo4j 图库 `Company` / `Contact` 节点属性（**camelCase**）  
> 入库约定：`conditions[].field` **必须**存 camelCase（如 `companyName`）；库中若出现 `company_name` 等 snake_case，视为旧数据  
> UI 对齐：与外呼任务流程条件组（`RuleConditionDTO`）交互一致

---

## 1. 概述

订单/任务在筛选目标 Leads 时，通过 **两个独立的条件组** 分别描述：

| 条件组 | 业务含义 | 存储字段 |
|--------|----------|----------|
| **公司条件** | 筛选符合要求的公司主体 | `company_conditions` |
| **联系人条件** | 在符合公司条件的结果上，进一步筛选联系人 | `contact_conditions` |

二者结构相同，均为 **JSON 对象**，不是独立关系表。

**例外：** 当目标范围为「指定公司名单」（`order_type = 2`）时：

- **订单**：名单明细存于 **`t_order_company`** 表；公司条件由服务端根据名单 **自动生成** 为单条 `companyName IN`（见 [§7.2](#72-指定公司名单order_type--2)）。
- **交付任务**：名单文件存于 `homework_url` / `homework_url_name`，条数存 `list_row_count`；公司条件同样归一化为单条 `IN` 写入 `company_conditions`。

读详情时返回且标记为只读（`fixed: true`）。

## 2. 存储位置

### 2.1 订单

| 表 | 字段 | 类型 | 说明 |
|----|------|------|------|
| `t_order` | `company_conditions` | TEXT | 公司条件组 JSON |
| `t_order` | `contact_conditions` | TEXT | 联系人条件组 JSON |
| `t_order` | `order_type` | TINYINT | `1` 条件筛选匹配；`2` 指定公司名单 |
| `t_order_company` | — | 明细表 | 仅 `order_type=2` 时使用，存上传名单 |

### 2.2 任务（改造后 homework 底座）

| 表 | 字段 | 说明 |
|----|------|------|
| `t_homework_configuration` | `company_conditions` | 同订单结构 |
| `t_homework_configuration` | `contact_conditions` | 同订单结构 |
| `t_homework_configuration` | `order_type` | 同订单：`1` 条件筛选；`2` 指定名单 |
| `t_homework_configuration` | `homework_url` / `homework_url_name` | 仅 `order_type=2` 时使用，名单 Excel OSS 地址 |
| `t_homework_configuration` | `list_row_count` | 名单解析条数 |

## 3. JSON 结构

### 3.1 条件组（ConditionGroup）

```json
{
  "logic": "AND",
  "conditions": [
    {
      "field": "companyName",
      "operator": "LIKE",
      "value": "科技"
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `logic` | string | 是 | 组内多条条件的组合逻辑：`AND`（且）或 `OR`（或）。非法/空值入库时归一化为 `AND` |
| `conditions` | array | 是 | 条件条目列表，可为空数组；入库时空列表整段 JSON 存 `null` |

### 3.2 单条条件（Condition）

| 字段 | 类型 | 必填 | 入库 | 说明 |
|------|------|------|------|------|
| `field` | string | 是 | 是 | 字段编码，见 [§4 可选字段](#4-可选字段元数据)。**入库标准为 camelCase**（如 `companyName`）；读写时服务端会把旧 snake_case 归一化 |
| `operator` | string | 是 | 是 | 运算符编码，见 [§5 运算符](#5-运算符)。入库前统一转 **大写** |
| `value` | string | 视运算符 | 是 | 条件值，格式见 [§6 条件值格式](#6-条件值格式) |
| `fixed` | boolean | 否 | **否** | 仅响应/展示用。`true` 表示前端只读（如指定名单生成的公司条件），**持久化时剥离** |

## 4. 可选字段（元数据）

字段列表由接口 **`GET /v1/orders/conditions/meta`** 返回；前端 `ConditionEditor` / `RuleConditionItem` 据此渲染：

- **`type: Enum` 且带 `options`** → 条件下拉选值（运算符为 EQ/NE/IN/NOT_IN 时）
- **`type: String`** → 文本输入（支持 LIKE、IN 逗号分隔等）
- **`type: Number`** → 数值输入（如参保人数）
- **`type: Datetime`** → 日期选择（如成立日期，值为 `yyyy-MM-dd`）

字段编码与 xleads-tools 图库属性名一致（camelCase），便于后续 Leads 检索对接。  
**meta 返回的 `field`、前端提交的 `field`、入库 JSON 的 `field` 三者相同**，不要写成 `company_name`。

### 4.1 公司条件字段（companyFields）

| field | label | type | 控件 | 说明 |
|-------|-------|------|------|------|
| `companyName` | 公司名称 | String | 输入框 | 企业全称或关键字 |
| `businessStatus` | 经营状态 | Enum | **下拉** | 存续、在业、吊销等工商状态 |
| `province` | 省份 | Enum | **下拉** | `optionsSource: region/province` |
| `city` | 城市 | Enum | **下拉** | `optionsSource: region/city` |
| `district` | 区县 | String | 输入框 | 如「余杭区」 |
| `companySize` | 公司规模 | Enum | **下拉** | L/M/S/XS（大型/中型/小型/微型） |
| `employeeScale` | 员工规模 | Enum | **下拉** | `dictCode: company_employee_scale` |
| `industryMajorCategory` | 行业大类 | Enum | **下拉** | `optionsSource: industry/major` |
| `industryMediumCategory` | 行业中类 | Enum | **下拉** | `optionsSource: industry/medium` |
| `legalPerson` | 法人代表 | String | 输入框 | |

| `englishName` | 英文名称 | String | 输入框 | |
| `keyWord` | 关键词 | String | 输入框 | 图库检索词字段 |

| field | label | type | 控件 | 说明 |

### 4.3 已下线字段（仅兼容旧数据，不再出现在 meta 下拉）

| 旧 field | 归一化后 | 说明 |
|----------|----------|------|
| `creditCode` / `credit_code` | `creditCode` | 统一社会信用代码；当前可选字段列表已移除，读旧数据时仍可推断类型 |
| `industry` | `industryMajorCategory` | 旧「行业」字段，读写时映射为行业大类 |

新编辑请使用 [§4.1](#41-公司条件字段companyfields) / [§4.2](#42-联系人条件字段contactfields) 中的字段。

### 4.4 下拉选项加载（方案 A：前端直连 xleads-tools）

meta 接口只返回字段定义；**有字典/远程源的字段不带 `options`**，由前端在选中字段后拉取：

| 机制 | meta 字段 | xleads-tools 接口 | 条件 value 取值 |
|------|-----------|-------------------|-----------------|
| 静态枚举 | `options: [{value,label}]` | — | `options[].value` |
| 通用字典 | `dictCode` + `optionValueKey` | `GET /v1/dictionaries/{dictCode}/items` | `employeeScale` 用 **itemName**（与图库一致） |
| 行业 | `optionsSource: industry/major` | `GET /v1/industries/tree` 展平 level=2 | 节点 `name` |
| 行业 | `optionsSource: industry/medium` | 同上展平 level=3 | 节点 `name` |
| 省 | `optionsSource: region/province` | `GET /v1/tagging/regions/cascader` 顶层 | 节点 `value`/`label` |
| 市 | `optionsSource: region/city` | 同上展平 children | 节点 `value`/`label` |

仍用 **meta 静态 options** 的字段（xleads 无标准字典）：`businessStatus`、`companySize`、`gender`、`hireStatus`。

前端实现：`conditionFieldOptions.js` + `RuleConditionItem` 选中字段后加载；网关前缀 `/api/xleads-tools`。

> **说明：** `String` / `Enum` 可用 [§5.1](#51-字符串类-string) 运算符；`Number`、`Datetime` 见 [§5.2](#52-数值类number)、[§5.3](#53-日期类datetime)。

## 5. 运算符

按字段 `type` 区分；也可调用 **`GET /v1/orders/conditions/fields/{fieldKey}/operators`** 获取某字段可用运算符。

### 5.1 字符串 / 枚举类（String、Enum）

| operator | label | symbol | valueType | 含义 |
|----------|-------|--------|-----------|------|
| `EQ` | 是 | `=` | SINGLE | 完全等于 |
| `NE` | 不是 | `!=` | SINGLE | 不等于 |
| `LIKE` | 包含文本 | `LIKE` | SINGLE | 模糊包含 |
| `NOT_LIKE` | 不包含文本 | `NOT LIKE` | SINGLE | 不包含 |
| `IN` | 是其中之一 | `IN` | ARRAY | 命中任一值 |
| `NOT_IN` | 不是其中任何一个 | `NOT IN` | ARRAY | 均不命中 |
| `IS_NULL` | 为空 | `IS NULL` | NONE | 字段为空 |
| `IS_NOT_NULL` | 不为空 | `IS NOT NULL` | NONE | 字段非空 |

### 5.2 数值类（Number，如参保人数 `insuredCount`）

| operator | label | valueType |
|----------|-------|-----------|
| `EQ` / `NE` / `GT` / `GTE` / `LT` / `LTE` | 比较运算 | SINGLE |
| `BETWEEN` | 介于 | RANGE |
| `IS_NULL` / `IS_NOT_NULL` | 空值判断 | NONE |

### 5.3 日期类（Datetime，如成立日期 `establishmentDate`）

与数值类运算符相同；`BETWEEN` 的 `value` 为 `yyyy-MM-dd,yyyy-MM-dd`。

---

## 6. 条件值格式

所有条件值在 JSON 中均为 **字符串** `value`；前端按 `valueType` 校验与展示。

| valueType | 适用运算符 | value 格式 | 示例 |
|-----------|------------|------------|------|
| `NONE` | `IS_NULL`、`IS_NOT_NULL` | 可不传或传空字符串 | `""` |
| `SINGLE` | `EQ`、`NE`、`LIKE` 等 | 单个文本/数字/日期 | `"阿里巴巴"` |
| `ARRAY` | `IN`、`NOT_IN` | **英文逗号**分隔多个值 | `"华东,华北,华南"` |
| `RANGE` | `BETWEEN` | **英文逗号**分隔起止，Date 为 `yyyy-MM-dd` | `"2025-01-01,2025-12-31"` |

## 7. 业务规则

### 7.1 条件筛选（order_type = 1）

- 公司条件、联系人条件均由用户在表单中编辑。
- 保存时：经 `OrderConditionSupport` 归一化后写入 `company_conditions` / `contact_conditions`（运算符转大写、`field` 转 camelCase、剥离 `fixed`）。
- 组内 `logic` 决定多条条件之间是「且」还是「或」。

### 7.2 指定公司名单（order_type = 2）

- **订单**：名单 Excel 解析后写入 **`t_order_company`**（`company_name`、`credit_code`）。
- **交付任务**：名单 Excel 上传 OSS，路径写入 `homework_url`；解析条数写入 `list_row_count`（无 `t_order_company` 明细表）。
- **保存时**：
  - **订单**：忽略客户端提交的 `companyConditions`，服务端按 `t_order_company` 生成 **单条 IN**。
  - **交付任务**：无名单表时，使用客户端提交的 `companyConditions` 并归一化为 **单条 IN** 入库。
- **生成规则**（入库形态，无 `fixed`）：

  ```json
  {
    "logic": "AND",
    "conditions": [
      {
        "field": "companyName",
        "operator": "IN",
        "value": "杭州示例科技有限公司,上海样本网络有限公司"
      }
    ]
  }
  ```

  - 语义：`companyName` **命中名单中任一公司**（`IN` / ARRAY，英文逗号分隔）。
  - **禁止**使用多条 `EQ` + `logic: AND` 表示名单（逻辑上不可同时满足多个公司名）。

- **读详情时** 返回上述条件的只读视图（`fixed: true`），前端不可增删改。
- 联系人条件仍可正常编辑，写入 `contact_conditions`。

### 7.3 兼容旧格式

**扁平数组（无 logic）：** 历史数据若存为 **扁平数组**（无 `logic` 包裹），服务端解析时自动迁移：

```json
[
  { "field": "companyName", "operator": "EQ", "value": "示例公司" }
]
```

等价于 `logic: "AND"` 的条件组。

**字段名迁移：** 读/写时服务端将旧字段名归一化为 camelCase。**当前入库标准就是右列 camelCase**；左列只出现在历史库值里。

订单生成推送交付任务时，会先 `parseGroup` 再 `toStorageJson`，不会把旧 snake_case JSON 原样拷贝到任务配置。

一次性清洗脚本：`crm-operation-homework-job/sql/schema/condition_field_camelcase.sql`（更新 `t_order`、`t_homework_configuration` 中条件 JSON 的 `field` / `fieldName`）。

旧 field → 新 field：

| 旧 field | 新 field |
|----------|----------|
| `company_name` | `companyName` |
| `contact_name` | `name` |
| `contact_phone` | `mobile` |
| `contact_title` | `position` |
| `registered_address` | `registeredAddress` |
| `credit_code` | `creditCode` |
| `industry` | `industryMajorCategory` |

**指定名单多条 EQ：** 若历史为多条 `companyName` / `company_name` EQ（旧版名单展开），读/写时服务端与前端均会 **自动合并** 为单条 `companyName IN`（逗号拼接 `value`）。

## 8. 相关 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/v1/orders/conditions/meta` | 返回 `companyFields`、`contactFields`（网关前缀 `/homeworkJob`） |
| GET | `/v1/orders/conditions/fields/{fieldKey}/operators` | 按字段返回可用运算符；`fieldKey` 支持旧名，内部会归一化 |

订单保存/详情、任务保存/详情接口的请求体/响应体中，字段名为：

- `companyConditions` — 公司条件组（camelCase）
- `contactConditions` — 联系人条件组

## 9. 数据示例

### 示例 1：条件筛选 — 公司「且」组合

**场景：** 行业大类包含「软件」，且注册地址包含「上海」。

```json
{
  "logic": "AND",
  "conditions": [
    {
      "field": "industryMajorCategory",
      "operator": "LIKE",
      "value": "软件"
    },
    {
      "field": "registeredAddress",
      "operator": "LIKE",
      "value": "上海"
    }
  ]
}
```

**入库 `company_conditions`（TEXT）** 为上述 JSON 单行字符串（无 `fixed` 字段）。

---

### 示例 2：条件筛选 — 公司「或」组合

**场景：** 公司名称是「阿里巴巴」**或**「字节跳动」之一。

```json
{
  "logic": "OR",
  "conditions": [
    {
      "field": "companyName",
      "operator": "EQ",
      "value": "阿里巴巴（中国）有限公司"
    },
    {
      "field": "companyName",
      "operator": "EQ",
      "value": "北京字节跳动科技有限公司"
    }
  ]
}
```

---

### 示例 3：IN 运算符 — 多值命中

**场景：** 行业属于「互联网,软件开发,信息技术」之一。

```json
{
  "logic": "AND",
  "conditions": [
    {
      "field": "industryMajorCategory",
      "operator": "IN",
      "value": "互联网,软件开发,信息技术"
    }
  ]
}
```

---

### 示例 4：联系人条件

**场景：** 职位包含「总监」，且联系电话不为空。

```json
{
  "logic": "AND",
  "conditions": [
    {
      "field": "position",
      "operator": "LIKE",
      "value": "总监"
    },
    {
      "field": "mobile",
      "operator": "IS_NOT_NULL",
      "value": ""
    }
  ]
}
```

---

### 示例 5：指定名单 — 读详情响应（含 fixed）

**场景：** `order_type = 2`，名单含两条公司（订单来自 `t_order_company`，或交付任务来自上传解析）。

**响应 `companyConditions`（VO，非库内原文）：**

```json
{
  "logic": "AND",
  "conditions": [
    {
      "field": "companyName",
      "operator": "IN",
      "value": "杭州示例科技有限公司,上海样本网络有限公司",
      "fixed": true
    }
  ]
}
```

**入库 `company_conditions`（由服务端生成，无 fixed）：**

```json
{"logic":"AND","conditions":[{"field":"companyName","operator":"IN","value":"杭州示例科技有限公司,上海样本网络有限公司"}]}
```

**同期 `t_order_company` 明细（仅订单）：**

| order_id | company_name | credit_code |
|----------|--------------|-------------|
| 1001 | 杭州示例科技有限公司 | 91330100MA2XXXX001 |
| 1001 | 上海样本网络有限公司 | 91310100MA2XXXX002 |

### 示例 7：空条件组

无有效条件时，库字段存 **`null`**（不写 `{}` 或空数组字符串）。

前端新建表单默认：

```json
{
  "logic": "AND",
  "conditions": [
    { "field": "", "operator": null, "value": "" }
  ]
}
```

提交前校验会要求可编辑行必须选择字段、运算符和值；`fixed` 行跳过校验。
