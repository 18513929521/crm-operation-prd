## 0. 产品层级说明

本PRD文档描述的是以下层级关系中的内容：

```
CRM产品（客户关系管理产品）
  └── 运营平台（Operation Platform）
       └── 系统管理应用（crm-operation-system）← 本PRD范围
            ├── 用户管理功能
            ├── 用户认证功能
            └── 内部接口功能
```

**层级定义**：
- **CRM产品**：顶层产品，包含多个平台
- **运营平台**：CRM产品下的运营管理平台，负责后台管理
- **系统管理应用**：运营平台下的应用，对应微服务 `crm-operation-system`
- **功能**：应用中的业务功能模块
- **操作**：功能中的具体操作

## 1. 需求背景

### 1.1 业务背景

随着企业数字化转型的深入，传统的CRM系统已无法满足企业多租户、多应用的管理需求。企业需要一个统一的运营平台来：

- **集中管理**：统一管理多个租户和应用的用户、权限、配置
- **灵活扩展**：支持快速接入新应用和功能模块
- **安全可控**：提供完善的权限控制和安全审计机制
- **高效运维**：降低运维成本，提升系统稳定性

**当前痛点**：
- 各应用独立管理用户，账号体系混乱
- 权限配置分散，安全风险高
- 缺乏统一的监控和运维工具
- 多租户数据隔离不彻底

### 1.2 用户角色

| 角色名称 | 角色描述 | 使用场景 | 典型用户 |
|----------|----------|----------|----------|
| 超级管理员 | 平台最高权限，负责整体配置 | 系统初始化、核心配置 | 技术负责人 |
| 系统管理员 | 负责用户和权限管理 | 用户管理、角色分配 | 运维人员 |
| 租户管理员 | 管理本租户的配置和用户 | 租户内部管理 | 企业管理员 |
| 普通用户 | 使用具体业务功能 | 日常业务操作 | 业务人员 |

### 1.3 需求来源

- **来源**：产品规划 + 客户需求
- **优先级**：P0（核心功能，必须实现）
- **预期上线时间**：2025-11-01
- **受益方**：平台运营方、租户企业、最终用户

## 2. 需求目标

### 2.1 核心目标

1. **建立统一的用户管理体系**
   - 实现用户的全生命周期管理
   - 支持用户的创建、查询、更新、删除操作
   - 提供用户状态管理（启用/禁用）

2. **提供安全的认证授权机制**
   - 用户登录认证
   - 基于Token的会话管理
   - 支持主动登出和会话失效

3. **支持服务间安全通信**
   - 提供内部接口供其他微服务调用
   - 实现Token验证机制
   - 确保服务间调用的安全性

### 2.2 成功指标

| 指标名称 | 当前值 | 目标值 | 衡量方式 |
|----------|--------|--------|----------|
| 用户操作响应时间 | - | < 1秒 | 接口响应时间监控 |
| 系统可用性 | - | ≥ 99.9% | 健康检查和监控 |
| 用户满意度 | - | ≥ 85% | 用户反馈调查 |
| 操作成功率 | - | ≥ 98% | 错误日志统计 |

#### 操作：创建用户

**原型图**：
![创建用户页面](../原型图/系统设置/系统设置-用户管理-新增用户.png)

**功能需求**：

1. **页面入口**
   - 位置：用户管理列表页面
   - 触发方式：点击页面右上角"新建用户"按钮
   - 展现形式：弹窗形式

2. **表单字段**

| 字段名 | 显示名称 | 类型 | 必填 | 校验规则 | 错误提示 | 默认值 |
|--------|----------|------|------|----------|----------|--------|
| 用户名 | 用户名 | 文本框 | 是 | 4-20位字母数字下划线 | 用户名格式不正确，应为4-20位字母、数字或下划线 | - |
| 密码 | 密码 | 密码框 | 是 | 8-20位，含大小写字母和数字 | 密码强度不足，应包含大小写字母和数字 | - |
| 确认密码 | 确认密码 | 密码框 | 是 | 与密码一致 | 两次输入的密码不一致 | - |
| 真实姓名 | 真实姓名 | 文本框 | 是 | 2-50位 | 姓名长度应为2-50个字符 | - |
| 邮箱 | 邮箱地址 | 文本框 | 否 | 标准邮箱格式 | 邮箱格式不正确 | - |
| 手机号 | 手机号码 | 文本框 | 否 | 11位数字 | 手机号格式不正确 | - |

3. **业务逻辑**
   - 用户名唯一性验证：创建前检查用户名是否已存在
   - 密码需要加密存储，前端不可见
   - 新用户默认状态为"启用"
   - 自动记录创建人和创建时间
   - 邮箱和手机号虽非必填，但建议填写

4. **操作流程**
   ```
   点击新建按钮 → 打开弹窗 → 填写表单 → 前端校验 → 
   提交数据 → 后端验证 → 保存到数据库 → 提示成功 → 
   关闭弹窗 → 刷新列表
   ```

5. **成功提示**
   - 显示消息："用户创建成功"
   - 提示样式：绿色toast，3秒自动消失
   - 弹窗行为：自动关闭
   - 列表行为：自动刷新，新用户显示在列表顶部

6. **失败场景**

| 场景 | 错误提示 | 处理方式 |
|------|----------|----------|
| 用户名已存在 | 该用户名已被使用，请更换 | 红色提示，停留在当前页面 |
| 用户名格式错误 | 用户名格式不正确，应为4-20位字母、数字或下划线 | 字段下方显示错误提示 |
| 密码强度不足 | 密码强度不足，应包含大小写字母和数字 | 字段下方显示错误提示 |
| 两次密码不一致 | 两次输入的密码不一致 | 字段下方显示错误提示 |
| 邮箱格式错误 | 邮箱格式不正确 | 字段下方显示错误提示 |
| 系统异常 | 系统繁忙，请稍后重试 | 红色提示，需手动关闭 |

**业务规则**：
1. 用户名全局唯一，创建后不可修改
2. 密码必须加密存储，界面上不可见原文
3. 邮箱和手机号非必填，但至少填写一项（建议）
4. 新创建的用户默认为"启用"状态
5. 自动记录创建人ID和创建时间

**注意事项**：
- ⚠️ 密码传输需要使用HTTPS加密通道
- ⚠️ 用户名不能包含特殊字符（仅支持字母、数字、下划线）
- ⚠️ 建议提示用户设置强密码，避免弱密码
- 💡 未来版本可考虑邮箱验证和手机号验证

**其他说明**：
- 创建成功后，可在列表中找到新用户
- 后续版本支持创建后立即分配角色
- 后续版本支持批量创建用户

#### 操作：删除用户

**功能需求**：

1. **页面入口**
   - 位置：用户列表页面的操作列
   - 触发方式：点击"删除"按钮
   - 展现形式：确认对话框

2. **删除方式**
   - 逻辑删除（软删除）
   - 数据不会真正删除，只是标记为已删除
   - 已删除的用户不在列表中显示

3. **删除限制**
   - 不能删除自己（当前登录用户）
   - 不能删除超级管理员
   - 需要二次确认："确定要删除用户"XXX"吗？"

4. **关联处理**
   - 清除用户的所有登录Token（强制下线）
   - 解除用户的角色关联（如有）
   - 保留用户的历史操作日志（用于审计）

5. **操作流程**
   ```
   点击删除按钮 → 弹出确认对话框 → 点击确定 → 
   执行删除 → 清除Token → 提示成功 → 刷新列表
   ```

6. **成功提示**
   - 显示消息："用户已删除"
   - 提示样式：绿色toast，3秒自动消失

**注意事项**：
- ⚠️ 删除操作不可恢复（逻辑删除）
- ⚠️ 删除后用户无法登录系统
- ⚠️ 需要记录删除操作到日志
- 💡 建议：提供回收站功能，可恢复误删用户（后续版本）

#### 操作：启用/禁用用户

**功能需求**：

1. **页面入口**
   - 位置：用户列表页面的操作列
   - 触发方式：点击"启用"或"禁用"按钮
   - 按钮显示：根据当前状态显示对应按钮

2. **业务逻辑**
   - **禁用用户**：
     - 将用户状态设置为"禁用"
     - 清除用户的所有登录Token（强制下线）
     - 禁用后用户无法登录
   - **启用用户**：
     - 将用户状态设置为"启用"
     - 启用后用户可以正常登录

3. **操作流程**
   ```
   点击启用/禁用按钮 → 弹出确认对话框 → 点击确定 → 
   更新状态 → （禁用时）清除Token → 提示成功 → 刷新列表
   ```

4. **成功提示**
   - 启用成功："用户已启用"
   - 禁用成功："用户已禁用"
   - 提示样式：绿色toast，3秒自动消失

**注意事项**：
- ⚠️ 禁用后用户立即无法登录
- ⚠️ 不能禁用自己（当前登录用户）
- 💡 状态变更需要记录操作日志

### 6.3 功能：用户认证（客户端接口）

**功能概述**：
提供用户登录、登出、获取当前用户信息等认证功能，供客户端（Web端、移动端）调用。

**功能目标**：
- 实现安全的用户认证机制
- 支持Token方式的会话管理
- 提供用户主动登出功能

---

#### 操作：用户登录

**原型图**
![用户登录](../原型图/运营平台-用户登录.png)

**功能需求**：

1. **登录表单**

| 字段名 | 类型 | 必填 | 校验规则 | 错误提示 |
|--------|------|------|----------|----------|
| 用户名 | 文本框 | 是 | 不能为空 | 请输入用户名 |
| 密码 | 密码框 | 是 | 不能为空 | 请输入密码 |

2. **业务逻辑**
   - 验证用户名和密码是否正确
   - 检查用户状态是否为"启用"
   - 生成JWT Token（有效期24小时）
   - 记录登录时间和登录IP
   - 返回Token和用户基本信息

3. **操作流程**
   ```
   输入用户名密码 → 点击登录 → 前端校验 → 
   提交到后端 → 验证账号密码 → 检查用户状态 → 
   生成Token → 记录登录信息 → 返回Token → 
   跳转到首页
   ```

4. **成功响应**
   - 返回数据：Token、用户ID、用户名、真实姓名、头像等
   - 客户端行为：保存Token到本地，跳转到首页
   - Token使用：后续请求都需要携带此Token

5. **失败场景**

| 场景 | 错误提示 | HTTP状态码 |
|------|----------|------------|
| 用户名或密码错误 | 用户名或密码错误，请重新输入 | 401 |
| 用户已被禁用 | 账号已禁用，请联系管理员 | 403 |
| 参数缺失 | 用户名和密码不能为空 | 400 |

**注意事项**：
- ⚠️ 连续登录失败3次后，需要输入验证码（后续版本）
- ⚠️ 记录登录失败日志，用于安全审计
- 💡 支持记住密码功能（后续版本）

---

#### 操作：用户登出

**功能需求**：

1. **页面入口**
   - 位置：页面右上角用户头像下拉菜单
   - 触发方式：点击"退出登录"
   - 展现形式：确认对话框（可选）

2. **业务逻辑**
   - 将当前Token加入黑名单（Redis存储）
   - 黑名单有效期等于Token剩余有效期
   - 清除客户端本地存储的Token
   - 跳转到登录页面

3. **操作流程**
   ```
   点击退出登录 → （可选）确认对话框 → 
   发送登出请求 → Token加入黑名单 → 
   清除本地Token → 跳转登录页
   ```

4. **成功提示**
   - 显示消息："已安全退出"（可选）
   - 直接跳转到登录页面

**注意事项**：
- ⚠️ 登出后Token立即失效，无法再使用
- ⚠️ 需要清除本地存储的所有用户信息
- 💡 登出可以不需要确认对话框，直接执行

---

#### 操作：获取当前用户信息

**功能需求**：

1. **使用场景**
   - 页面加载时获取当前登录用户信息
   - 用户头像下拉菜单中显示用户信息
   - 个人中心页面展示详细信息

2. **业务逻辑**
   - 从请求Header中获取Token
   - 验证Token是否有效（未过期、未在黑名单）
   - 解析Token获取用户ID
   - 查询用户详细信息
   - 验证用户状态是否为"启用"

3. **返回信息**
   - 用户ID
   - 用户名
   - 真实姓名
   - 邮箱
   - 手机号
   - 头像URL
   - 用户状态
   - 最后登录时间

4. **失败场景**

| 场景 | 错误提示 | 处理方式 |
|------|----------|----------|
| Token未提供 | 未登录，请先登录 | 跳转到登录页 |
| Token已过期 | 登录已过期，请重新登录 | 跳转到登录页 |
| Token已失效 | 登录已失效，请重新登录 | 跳转到登录页 |
| 用户不存在 | 用户不存在 | 跳转到登录页 |
| 用户已禁用 | 账号已被禁用，请联系管理员 | 显示错误页面 |

**注意事项**：
- ⚠️ 每次页面刷新都需要重新获取用户信息
- ⚠️ Token验证失败时，需要清除本地Token并跳转登录页
- 💡 可以考虑将用户信息缓存到本地，减少请求次数

### 6.4 功能：内部接口（服务间调用）

**功能概述**：
提供给其他微服务调用的内部接口，用于服务间的用户信息获取和Token验证。

**功能目标**：
- 支持其他微服务获取当前用户上下文
- 为网关提供Token验证能力
- 确保服务间调用的安全性

#### 操作：获取当前用户信息（内部）

**功能需求**：

1. **使用场景**
   - 其他微服务需要获取当前请求的用户信息
   - 通过Feign客户端调用
   - 用于业务逻辑中的权限判断

2. **业务逻辑**
   - 从Header中获取Token
   - 验证Token有效性
   - 返回用户完整信息

**注意事项**：
- ⚠️ 此接口仅供内部微服务调用
- ⚠️ 应通过内网访问，不对外暴露
- 💡 后续考虑增加IP白名单限制

---

#### 操作：验证Token有效性

**功能需求**：

1. **使用场景**
   - 网关验证请求的Token是否有效
   - 判断用户是否有权访问
   - 高频调用，需要高性能

2. **业务逻辑**
   - 接收Token参数
   - 验证Token格式、有效期
   - 检查Token是否在黑名单中
   - 查询用户并验证状态
   - 返回验证结果和用户基本信息

3. **返回信息**
   - valid：true/false（是否有效）
   - userId：用户ID（有效时返回）
   - username：用户名（有效时返回）
   - realName：真实姓名（有效时返回）
   - reason：失败原因（无效时返回）

**性能要求**：
- 平均响应时间：< 100ms
- 99%响应时间：< 200ms
- 支持高并发调用

**注意事项**：
- ⚠️ 此接口设计为始终返回200状态码，通过valid字段判断
- ⚠️ 适合网关等高频调用场景
- 💡 返回格式友好，便于调用方处理
